## 1 今天确认了什么

1. 当前优先链：QQ → DSH 会话 → 记忆 → 会话连续性 → 情绪与人格演进。视频等能力暂缓，长期目标保留。
2. “她是大肥鱼”与“对主人的信任”不可变；其他性格可随经历缓慢变化。模型不得通过记忆描述或其他关系维度绕过这两项约束。
3. 记忆需要覆盖用户消息、大肥鱼实际回复与显式反思；思考中的猜测、已发言、草稿和发送结果必须分开。
4. 本轮授权是整理、按模块提交和推送；不连接真实账号，不安装组件，不进入产品开发。

## 3 当前建议与实现差距

- 每个私聊、每个群各有独立交流场景；DSH session 可替换，同一 life_id 的身份与领域状态持续保存。不是给每人复制一个人格。
- LifeCore 负责领域状态和授权；DSH 运行推理与工具；SnowLuma 提供 QQ 通道。现有 `llm.stream` 预览尚未完成连续 Agent/session 接入。
- 复用 SeekMemory 窄候选处理优先，LifeCore 唯一正式提交。上游独立运行时、人格刷新与主库不同时接入；中文检索和依赖隔离仍需验证。
- 情绪即时、有界更新；关系多维、有方向且带证据；人格依据多次独立经历缓慢变化。反思与摘要不能变成额外证据。
- 纠正先阻断旧依据，再修订记忆、重算派生状态和更新上下文。程序规则能限制影响，不能证明模型语义判断永远正确。
- 关系密切不自动授予分享权限；已发送内容、未发送草稿、未知结果不同。新会话不等于清空人生。
- UI 复用现有本地管理入口和轻量前端；本次草图另存文档目录，未替换 `web/` 页面。

## 4 保留的决策和验证事项

最重要的产品选择：是否允许有限全局心境/抽象人格影响其他场景的语气。最新建议允许，但不提供私聊原文、原因或对象感受；较早方案则严格按场景可见贡献重算。两者的隐私承诺不同，本轮提交推送不代表已选择其中之一。

还需明确或验证：首轮联系人/群范围、手动新会话话题延续方式、情绪衰减与演进预算、模型调用延迟和费用、中文检索质量、DSH 发行版本接口及恢复能力。此前固定源码阅读不等于发行包可直接运行。

独立设计复核的结论和范围保存在对应文档；最新复核认为除明确保留的跨场景状态共享选择外，无影响制定实施计划的重要遗漏。界面检查只验证合成数据、布局与本地交互。Q01–Q12、R01–R10 及此前故障/记忆验收仍需在实现后执行。
