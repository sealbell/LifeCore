## 1 目标与已确认选择

维护者希望大肥鱼优先记住双方的共同经历和重要事情，延续同一段生活。她自己判断哪些经历值得重点保留，不逐条请求确认；用户可以事后查看、纠正和删除。自动判断是模型提出有依据的候选、程序校验后自动提交，不是允许模型绕过规则直接写库。

本轮在现有 M01–M15 内细化 M04/M09，不新增独立记忆服务器，不改变一个正式生命、统一提交和场景隔离方向。分层与调用草案的其他部分仍保持原来的待确认状态。

| 考虑过的路线 | 收益与代价 | 选择 |
| --- | --- | --- |
| 只增加聊天摘要 | 较轻，但难以处理共同经历、变化事实、来源与删除 | 未选择 |
| 在既有模块内细化记忆和上下文契约 | 保持模块归属，补全形成、保留、召回和纠错链路 | 维护者已选择 |
| 完整记忆平台与自动技能学习 | 能力更广，但增加首版验证与维护负担 | 后置 |

目标是：重启后能回忆共同经历；重要事情不因退出上下文窗口而消失；过去与现在可区分；没有证据的细节不补写；用户修正能持续生效。

本版不承诺保存每一句话、不设无限存储，不实现自动生成可执行 Skill、不用记忆权重直接修改人格。全文检索、结构化查询及 SQLite 延续现有推荐方向，具体技术和阈值仍待验证。

## 3 记忆材料及语义字段

以下是语义约定，不是数据库表或冻结的接口字段名。

| 材料 | 内容 | 规则 |
| --- | --- | --- |
| 共同经历 | 谁参与、何时何地、双方实际做过什么、经过与结果 | 基于 M03 情节；可跨多轮/多日，不把时间接近或词语相同当作同一经历的充分条件 |
| 重要事实 | 称呼、偏好、重要日期、已经确认的选择 | 按主体与属性读取，带陈述来源、有效时间和冲突状态 |
| 重要时刻 | 相识、共同完成目标、重要约定、关系转折等 | 是经历的里程碑标记和表达，不再复制一份独立成长证据 |
| 近期摘要 | 当前场景话题、关键实体、未完问题、已确定与未确定事项 | 覆盖区间明确；持久化以支持重启；不含另一个场景的私密材料 |
| 反思与理解 | 她对经历意义的解释 | 与事实分开；置信不足时保留不确定性，不从反思生产新事实 |

一段经历至少包含：

- 身份：记忆标识、正式 life_id 或试聊工作区标识、情节标识、版本。
- 经过：发生时间范围及精度、参与者、场景、主要行为、已知结果和未解决事项。
- 来源：来源事件及版本、关键证据片段、观察/陈述/解释/行动结果类别；主要断言能对应具体来源。
- 意义：重要性理由类别、证据引用、判断来源（她自动判断/用户指定）、评价版本。
- 状态：有效/有争议/被替代/已删除等可用性；普通/重点保留分类；原文可查/仅摘要等证据完整度。
- 约束：可见范围、来源依赖、保留策略引用及期限、人工覆盖、修订与删除关联。

这几组状态相互独立：重要但有争议的经历可以保留；仅剩摘要不等于整段无效；被替代的旧事实可用于历史查询，但不当作当前状态。

共同经历的认定必须有她参与的事件依据。用户讲述自己的旅行，可记为“你向我讲过这次旅行”；不能变成“我们一起去过”。拟发送回复不是双方已经发生的交流，发送结果依 M11 回执判断。

多场景材料不因同属一个情节而自动合并可见性。同一情节可有不同来源范围的记忆表达；聚合表达取来源限制交集，没有合法共同范围就分开。跨平台身份绑定不自动允许跨场景回忆，公开表达不能泄露私密片段或其存在。

## 4 自主判断重要性

### 4.1 判断依据与自动提交

建议把重要性表示为可解释的理由组合，而非只显示一个分数：

| 依据 | 例子 | 限制 |
| --- | --- | --- |
| 首次与独特性 | 正式出生后第一次交流、第一次共同完成某件事 | 首次要在对应对象/事件类别内核验；缺历史时标为已知最早，不虚构绝对首次 |
| 共同投入与结果 | 反复讨论后确定了一个重要选择 | 需要真实参与和结果证据，纯计划不能当完成 |
| 对未来的持续影响 | 约定、边界、明确变化的偏好 | 承诺执行与关系规则仍归其原模块 |
| 关系或生活转折 | 误解后和解、重要告别 | 解释需引用事件，不能单凭情绪词推断关系已经改变 |
| 用户明确强调 | “这件事对我很重要”“请记住” | 记录发言来源；不赋予管理权限或无限保存权 |

流程：模型根据有限材料提出“是否重点保留、理由、具体证据、仍不确定什么”；M04 验证引用、材料类别、重复性和适用规则；M02 结合 M12 与保留限制自动提交。用户无需逐条批准，也不会每条收到记忆通知。

重要度、事实可信度、当前相关性、回忆频率分别保存和使用。重复刷屏、转载、模型自己的重述，以及同一事件的多个摘要都不能被计算为新的独立经历。单次强烈情绪可以支持重要记忆候选，不直接放大关系或人格变化。

判断不确定时先保存有依据的普通记忆和待评估原因，后续有新证据再提升。不得通过编造“对我们意义重大”来填充理由。用户明确要求重点保留时，可直接形成带用户来源的保留候选，仍执行权限与保留校验。

### 4.2 重点保留的具体含义

建议的默认行为：

1. 重点经历摘要、关键证据和来源关系进入长期保留类别；在相同相关性下获得更稳定的召回机会。
2. 不受普通记忆显著性衰减或原始聊天的常规滚动清理直接淘汰，但仍受既有硬性保留期限、删除请求及授权撤销限制。
3. 只按需要保存最少关键原文片段，作为独立、受来源限制的证据材料登记；不通过复制整段聊天隐式无限延长保留期。
4. 普通原文的滚动期限与来源的硬性期限分别处理：前者允许在既定重点保留政策下保存必要片段，后者约束所有副本和摘要。既有来源不允许长期保留时，只显示受限状态，不偷偷延长。
5. 重点记忆不会因为未被召回而自动降级或删除；她可以提出重新分类理由，原来的重点保留继续有效，用户可以主动改回普通。
6. 重点保留不保证每次都回忆，也不授权主动发送消息、共享隐私或反复提及令人不适的经历。

具体普通消息期限、重点保留容量、评估阈值和周期尚未确认。建议正常可用容量内优先保留重点材料；接近容量限制时压缩允许压缩的普通材料并在管理端提示。空间不足以可靠保存时停止新增持久化并报告失败，不静默淘汰重点记忆，也不声称已经记住。

### 4.3 人工决定具有持续效力

查看、改回普通、纠正和删除是已授权管理操作，走 M15 → M02，绑定真实管理主体、目标版本与幂等标识。模型不能用聊天里的“我是主人”取得这些能力。

用户将某段经历改回普通后，记录针对该经历的人工覆盖；同一来源重算、摘要更新和模型替换都不能把它重新提升。用户可以解除覆盖。真正的新经历独立判断，不能通过复制或改标题绕过原覆盖。

人工纠正绑定被纠正的断言、来源和适用时间，不把某次纠正冻结成永久不变的个人事实。此后用户明确表示偏好发生变化时，可以增加新有效区间；不能以“新版本”为名重新使用已纠正的旧来源。范围无法判断时保留冲突，不静默覆盖任一版本。

一般聊天里的“你记错了”先作为带来源的纠正事件；可更新该发言者对自己偏好的陈述，但不自动获得改写所有人记录或删除数据库的权限。首版的确定管理入口是 M15；聊天管理能力需另行完成身份与操作绑定设计。

## 5 形成与更新流程

1. M02 经 M03 去重并持久入账，保存源事件及处理任务。模型不可用不影响已成功入账的事实。
2. M02 在当前回合或后台维护任务中，委托 M09 在允许材料上整理记忆候选；不要求每条短消息都额外调用模型。
3. M03 校验新增情节关联，M04 校验表达、断言依据、事实变化、重要性、来源权限和人工覆盖；无效候选保留错误类别供重试，不进入可回忆集合。
4. M02 比对来源版本、删除状态、相关状态版本与策略，在 M13 事务中保存记忆修订、依赖关系、保留分类和处理检查点。
5. M13 更新可检索视图；异步索引落后时以权威版本为准，禁止返回已失效内容。记忆写入成功与索引可检索状态分别呈现。
6. 新事件延续旧经历时追加版本与来源；事实纠正建立替代关系。保留历史修订的前提仍是未触发删除与期限清理。

经历封段以明确完成、话题转换或可配置的空闲间隔为线索；首版可以暂存待续经历，不因程序重启强制结束。不同日期的事件只有明确的延续指向或可核验关联才归入同一情节。具体分段参数留给合成用例校准。

抽取幂等依据是来源集合及版本、处理类型与处理版本；不能只比较摘要文字。更新处理版本产生同一记忆的修订，不新增独立经历或再次累计成长。

维护任务可由会话阶段结束、来源累计到预算阈值、待处理任务到期或清理前检查触发，经 M02 调度并持久化检查点。未完成重点评估的来源不能被清理任务悄悄越过；任务不能无限延期硬性删除期限，到期宁可放弃整理也不违规保留。暂停期间不运行模型维护，重启后在预算内继续，不产生补发社交消息。

## 6 时间、冲突与证据

每个会变化的事实至少区分系统记录时间与已知有效时间/区间。事件自身继续使用 M03 的发生/接收时间和提交顺序；不要求所有聊天材料采用完整双时态数据库。

例如“以前不喜欢某种音乐，现在开始喜欢”：保留旧陈述及有效区间，当前查询返回新陈述；历史查询按所问时间取值。晚收到“上个月不喜欢”的消息不能覆盖今天的偏好。

来源不同、时间不明确或无法解释的矛盾标为有争议，返回带出处的有限候选，不靠最新写入、最长文本或最高重要度强行选择事实。用户的自述是可追溯陈述，不等于系统独立核验的外部事实。

摘要中的每项关键断言保留来源关系。缺证据的情绪和关系推断退回解释类别；准确引语仅来自可查原文。原文普通到期后允许保留的摘要须标记证据完整度变化，不能从摘要重新生成伪原文。

## 7 召回规则与接口语义

M09 通过受限查询服务请求，M04 只负责规则。请求包含可信场景句柄、生命/工作区、当前对象、触发事件、查询目的、时间范围、相关情节线索和容量预算；场景/主体由可信运行时绑定，模型不得自选扩大范围。

建议分两条路径：

- 精确路径：已验证人物标识、事实属性、情节标识、承诺引用等，读取对应权威对象或记忆，避免手机号/日期依赖语义相似度。
- 回忆路径：在授权候选内结合对象、全文匹配、情节关联、时间线索、重要性与证据质量排序。同一经历多个摘要去重；对自然联想加入近期已提及抑制，不强迫每次提起同一里程碑。

优先满足明确对象、时间和主题；重要性只在相关候选中发挥作用，不把无关重大经历硬塞进每轮聊天。首版中文检索须用中文短句、称呼和别名的合成用例验证分词/匹配方案，不能仅以启用 SQLite 全文索引宣称可用。向量检索后置。

返回材料包括记忆标识与版本、有限正文、情节/来源关联、来源类别及可查性、有效时间、冲突/完整度、召回理由、可见范围和依赖版本。自然联想还提供当前授权场景内的近期提及信息；详细证据只在当前权限允许时返回，无权材料的标题、命中数和拒绝理由不向社交模型透露。

读取不改变重要性、关系或人格。召回统计如需持久化，通过独立、幂等的 M02 维护请求记录；它不成为成长证据。对话中已经发送的提及依据 M11 结果记录，候选回复不算用户已经听过。

与 M09 配合的主动回忆提案：主动联想开关开启时，基础召回可由当前话题的具体关联触发，不要求显式回忆指令；相关性和对当前交流的帮助先于重要性。M04 用同情节、共享来源和已表达事实点识别重复候选，摘要改写或情节合并不清空已提及关联；M09 决定简短带出、仅用于理解或不使用。候选都不合适时返回不足，不为避免重复而塞入无关回忆。

关闭主动联想不停止 M04 的记忆形成、自动重点保留和管理，不删除或降级既有记忆。M09 跳过仅为自发联想的召回，明确追忆、必要话题延续和当前事实查询仍使用原有受限接口。开关管理与切换语义见 M09 第 7.0 节；重新开启不重置已提及记录。

M02/M13 保存同场景提及计划与实际结果，M11 提供发送回执；M04 只读使用。待发送/结果未知的同类自发提及暂时避让，不能据此记为用户已看过；失败解除避让。显式追问和正常话题延续可绕过主动重复抑制，但不能绕过权限。记录及停止提及标记均受来源、场景、期限和删除规则约束，不是第二套关系或人格状态；具体语义以 M09 第 7 节为准。

## 8 查看、纠正、删除与恢复

M15 需要提供的产品能力：查看经历内容、时间、来源、为何重点保留、自动或人工决定、当前版本、原文可查程度和保留限制；筛选重点经历；纠正内容；改回普通；删除。这里只定义功能和结果，不冻结界面布局。

纠正操作保留“原有认识”和“此次管理纠正”的关系；新查询优先使用纠正版本。受影响摘要先失效，再按仍可用来源重建。用户修正不能伪装成当年说过的话；模型后续重算不能覆盖管理修订。

删除按来源依赖展开：原文及关键片段、记忆正文和旧版本、摘要、自传表达、全文/向量索引（若未来启用）、附件缓存、待处理材料、提及记录/停止提及标记中的内容引用、诊断中的内容副本及受影响宿主上下文。共享来源支持的混合摘要先整体禁用，再从未删除来源重建；不能仅删一个界面上的卡片。

管理删除需要说明范围：删除整段经历时覆盖其来源和派生物；删除来源中的一部分时禁用依赖该部分的派生物，并保留无关材料。保留不含被删内容的最小抑制标识，阻止同一来源重新导入或重新抽取；对未来用户主动重新讲述的新事件不承诺语义永久封禁，也不保存被删正文用于匹配。

删除首先通过 M02 提交读取/出站阻断和删除代次，阻止新查询、后台重建及在途提案复活内容；物理清理可分批重试。状态区分“已停止使用”“清理中”“本机清理完成”“备份处理状态”，不能提前宣称所有副本均已删除。旧备份恢复先应用删除清单再开放查询与联网。已经发送到外部平台/模型服务的内容无法仅靠本机删除撤回。

M07 受影响证据按既有原则失效并生成后续修订；M06/M08 等派生状态由各自规则处理，M04 不直接归零关系或取消承诺。删除请求必须收集跨模块依赖并由 M02 组织处理；在处理完成前相关派生解释不得继续供回忆。外部动作已执行的事实与被删正文分开，不能因删记忆把已完成动作改成未执行。

## 9 失败与恢复行为

| 情况 | 设计行为 |
| --- | --- |
| 摘要或重要性判断失败 | 原事件已入账则保留；持久任务按有界策略重试，普通回忆可使用允许的原始事件；不伪造记忆保存成功 |
| 模型结果迟到或来源被纠正/删除 | 提交前校验版本和删除代次；丢弃失效候选或用最新材料重算，不覆盖人工修订 |
| 重复事件、插件重载 | 依据来源去重与处理检查点继续，不重复新增经历、保留评价或成长证据 |
| 索引落后或重建 | 权威状态过滤；优先精确查询/有限原文读取，缺结果明确降级；不复用失效索引文本 |
| 存储写入失败或容量不足 | 不确认保存；暴露本地诊断和受影响范围，保持已有重点记忆；恢复后受控重试 |
| 删除中断或旧备份恢复 | 阻断持续有效；继续清理；恢复先应用删除及人工覆盖约束，再允许检索 |
| 模型替换 | 已提交经历与人工修订不重写；重抽取是显式带版本维护任务，不重复成长 |

## 10 验收场景

以下是后续设计验收用例，不表示已执行软件测试。使用合成材料，不上传真实私聊。

| 场景 | 可观察结果 |
| --- | --- |
| 一起选名字，未说“请记住” | 自动生成重点候选并经校验提交；管理端可看到双方行为与重要理由，无逐条确认 |
| 只是告诉她旅行经历 | 表达为“你告诉过我”，不变成双方共同到场 |
| 多轮跨日延续同一项目 | 相关事件归为一段可追溯经历，结果随实际回执更新 |
| 重启后问起重要时刻 | 同一身份可召回已提交经历与来源；不依赖旧聊天窗口 |
| 连续转发同一消息、反复生成摘要 | 不增加独立经历、重要性证据或人格成长证据 |
| 主动联想开启、相关话题未明确要求回忆 | 可提供贴切经历和近期提及信息，让 M09 自然使用；不以提及次数作为成长证据 |
| 主动联想关闭 | 记忆照常形成和重点保留，明确回忆可查询；不以此为由删除历史或清空提及记录 |
| 同一经历换摘要后再次进入候选 | 沿情节/来源识别已经表达的事实点，避免同一故事换措辞重复出现 |
| 一次争执与后续和解 | 能保留经过和修订理解，不能把一次情绪直接固化为永久关系判断 |
| 过去与当前偏好冲突、旧消息晚到 | 分开时间和来源；不让晚写入的旧事实覆盖现在 |
| 人工纠正或改回普通后重抽取 | 人工决定仍有效；不能因改摘要标题重新提升 |
| 重点原文到期 | 按来源政策保留允许的必要片段或摘要；标明证据完整度，不声称保留了全部原话 |
| 删除来源时后台摘要尚未返回 | 迟到候选被拒绝，摘要、索引、宿主上下文不可继续使用被删材料 |
| 删除后恢复旧备份 | 先应用删除清单，不能重新出现经历、标题或派生摘要 |
| 人工纠正旧偏好后，用户又明确改变偏好 | 原纠正对旧时段继续有效，新陈述建立新的有效时段；不永久冻结旧值 |
| 首次经历只发生在未选中的试聊 | 正式记忆不包含；确认导入部分仍标记初始材料，不算出生后自然成长证据 |
| 重点内容超过可用空间 | 显示无法新增保留与容量原因，不静默删除已有重点材料 |

## 11 跨模块交付与尚待确定事项

本设计向 M02/M03/M12/M13/M14/M15 提出来源依赖、人工覆盖、删除代次、受限记忆包和管理可解释性等语义契约；M05/M06/M07/M08/M11 继续拥有自身状态。共用契约摘要登记在 V1，不能据此推定其他模块的详细接口已经批准。

本稿作者建议、待维护者确认：重点经历不按普通衰减自动降级；重点保留优先保存摘要和必要证据；人工降级/纠正持续覆盖自动重算；检索后是否提及由 M09 再判断。

已确认自然回忆偏好：用户通过开关选择主动联想，开启时相关便可更主动、自然提起且避免重复。仍需产品选择：开关默认值、原文与重点材料具体期限/容量、自动保留通知是否仅放管理端。近期抑制窗口与提及记录保留参数留待校准；未确定数值不妨碍继续讨论语义，但在实现前必须形成明确配置和失败策略。

留给实施设计：类型及表名、索引/中文匹配实现、分段参数、重要性校准、重试次数、任务批量、管理页布局。来源参考是本仓库 V1/总体设计及本次视频讨论；视频只提供分层/时效/派生视图启发，不是已经验证的依赖或实现。
