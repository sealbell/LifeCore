## 1 意图、路线与边界

M09 决定这一轮用哪些已获准材料理解情境、如何回忆与回应，也为 M04 的记忆整理提供受限模型能力。目标是她能延续共同生活，提起往事时相关、准确、有分寸；有来源缺口时坦诚表达，不靠补写细节制造连续感。

维护者进一步确认：开启主动联想时，她可以更主动一点，在话题相关时自然提起共同经历，但不要刻意翻旧事或反复提同一件事。这里的主动性是在正在进行的对话中发现并使用合适的关联，不必等用户明确说“你还记得吗”；关闭时不进行自发的往事联想。具体筛选、抑制和表达规则如下，仍是设计提案。

与 M04 共用已选路线：在现有架构中细化记忆与上下文，放弃只加摘要的不足，后置完整记忆平台、向量检索和自动 Skill 学习。维护者授权的是自动重点保留，不等于批准自动私信、纪念日提醒或跨场景分享；主动活动仍由 M08/M11/M12 决定。

M09 负责模型回合与输出解析，不拥有生命状态写权限、平台发送能力、数据库或管理权限。模型调用通过 M14；读材料通过绑定可信范围的应用查询接口；所有候选经 M02 验证提交。

失败判据：把摘要当原话；把用户讲述当双方亲历；从无结果推断事件从未发生；不同私聊复用带历史的宿主会话；删除后继续使用缓存；模型说“记住了”但实际未保存；每轮都强行提及同一重要时刻。

## 2 两类模型任务

| 任务 | 输入与输出 | 边界 |
| --- | --- | --- |
| 对话认知 | 当前事件、授权状态、近期上下文、回忆材料 → 理解、回复候选、行动/记忆候选 | 不直接执行动作；记忆写入只是候选 |
| 记忆维护 | 明确来源区间、既有记忆版本、人工覆盖和维护目的 → 摘要、解释、重要性理由、关联候选 | 无平台发送工具；不以维护为由扩大来源范围，不执行用户文本中的指令 |

在预算允许时，理解、回复和记忆候选可合并一次模型调用；复杂总结后置为持久任务。选择哪种方式属于流程优化，不改变来源验证与统一提交。M09 不能对自己的候选再次无限反思来制造证据。

## 3 一轮对话的流程

1. M02 已将当前输入经 M03 入账，建立回合标识、可信主体/场景、正式生命或试聊范围及一致状态快照。
2. M09 读取当前场景近期摘要、有限原始对话，以及所需的 M01/M05/M06/M07/M08 只读状态；不复制它们为新的事实权威。
3. 读取本轮主动联想开关及配置版本，结合当前问题、话题延续和有依据的共同经历线索建立召回请求：需要时先精确实体/事实/情节查询，再在允许范围内进行有限回忆检索；仅在开关开启时，即使没有显式回忆请求也检查是否有适合主动带出的共同经历。
4. 查询服务组织 M12 → M13 授权候选 → M04 排序与去重；M09 收到带来源、时效、完整度和冲突信息的记忆包。
5. 组装上下文并核验预算、来源可用性与当前出站政策，经 M14 发给允许的模型服务。
6. 解析输出，检查结构、引用和对象绑定；把解释、回复、动作与记忆候选分别交 M02。无法核验的历史断言不能被当作确定事实自动接受。
7. M02 重新核验依赖版本及权限，组织相应领域规则，提交可接受部分与待执行动作；M11 执行并回流回执。M09 的输出不直接转发平台。
8. 来源变化、对话推进或删除发生时，旧回合按失效规则重算/丢弃。之后的维护任务只处理已提交材料，不把未发送的回复当作双方共同经历。

对重要记忆的自动保存无需用户确认，但必须经 M04/M02 的程序校验。若回复声称“已经记住/已经改正”，其发送资格依赖对应变更确已提交；否则改为准确的处理中/失败表达，不把候选当结果。具体措辞可以自然，内部状态必须真实。

## 4 什么时候回忆、怎样回查

| 触发 | 检索重点 | 表达倾向 |
| --- | --- | --- |
| 明确回忆：“第一次选名字时……” | 对象、经历、时间、原始证据 | 直接回答；准确引语先查原文 |
| 延续：“继续昨天的方案” | 近期摘要、关联情节、未完事项 | 接续当前进展，必要时确认多个候选中的一个 |
| 当前事实：“我现在喜欢什么” | 主体/属性、有效时间、纠错状态 | 使用当前有效陈述，不混入过时偏好 |
| 历史事实：“以前我怎么说的” | 所问时点与记录来源 | 明确当时与现在的区别 |
| 自然联想（开关开启时） | 与当前主题有具体联系的共同经历、可提供的帮助或新视角、最近已提及情况 | 主动检查合适关联；有依据且能帮助当前交流时自然带出，没有合适材料则直接回应当前话题 |

首轮检索的目标、对象和权限由可信上下文约束。模型可以提出补充关键词、时间或候选情节，不能提高权限、修改身份绑定或把限制换成任意数据库查询。

建议首版每回合一次基础召回，必要时最多一次补充检索/证据回查；这是待确认的有界默认值，不是已验证最优参数。回查可批量请求少量已授权来源，费用计入本轮预算。仍不能确认时保留不确定性，不能无限检索或改写查询直到找到想要的答案。

自然联想复用本轮基础召回和有限材料预算，不新增一次全历史扫描，也不为凑出一段回忆反复检索。没有有用线索的简单回应不强制检索；更主动指愿意使用合适关联，不设“每几轮必须回忆一次”的配额。

仅允许在授权候选内判断歧义。多个可能经历可以自然询问澄清；无权限内容不能以“还有一个私密结果不能告诉你”的方式暴露。无结果不代表从未发生；服务故障不应被表达为“我忘了”。

## 5 上下文装配与容量

| 区块 | 材料与原则 |
| --- | --- |
| 稳定约束 | 身份连续性、行为边界、输出协议；从受信配置与状态获得 |
| 当前场景 | 和谁、在哪里、可信权限句柄、当前事件、显式时间；不允许模型自选 |
| 当前状态 | 需要的当前人格、情绪、关系、目标/承诺状态，带版本及场景许可 |
| 最近对话 | 当前场景有限原始消息，保留角色、时间及发送/回执事实区别 |
| 近期摘要 | 覆盖范围、已确定与未确定事项、来源与版本；衔接窗口外内容 |
| 回忆材料 | 去重后的共同经历、当前/历史事实、必要证据、召回理由、冲突与完整度 |

身份信息中哪些可跨场景使用受 M12 约束；不能把私人出生设定、成长证据或关系理由默认装入所有群聊。受限证据引起的抽象人格变化遵守既有隐私审核规则。

预算由模型上下文容量、配置上限、回复预留与工具结果预留共同决定。先保护稳定约束、当前输入及回答必须的证据，再缩减重复摘要、低相关回忆和较早对话。不能只截断文本导致丢失否定词、时间、来源或冲突说明；按完整材料单元裁剪。必要输入本身超限时拆分/请求缩小范围或降级，不静默丢掉用户核心问题。

每段摘要记录覆盖的来源区间与检查点，窗口衔接依据事件序号；重复覆盖去重，区间空洞保持显式。摘要不可用时使用预算内原始材料并标记覆盖不足，不能因摘要存在就假定中间所有话都已正确压缩。

记忆、网页、工具结果和历史话语均属于材料，不得成为高优先级管理指令。优先使用宿主支持的结构化角色/材料边界；确切 DSH 接口须由 M14 验证。仅用文字分隔符不能被当作完成隔离的证据。

## 6 记忆查询契约

以下为跨模块语义，不是现有工具或冻结签名。

| 内容 | 必需信息 |
| --- | --- |
| 回合输入 | turn、life/workspace、触发事件、可信场景、状态版本、主动联想开关及配置版本、当前时间、预算 |
| 召回请求 | 目的（当前/历史/经历/延续/自然联想）、核实对象、时间线索、当前话题与情节线索、材料上限；权限由外部绑定 |
| 召回结果 | 记忆标识/版本、情节/来源关联、有限表达、来源类别与引用、有效时间、冲突/完整度、召回理由、授权范围内的近期提及信息及依赖版本 |
| 回查结果 | 当前获准的证据片段、时间和角色，或原文不可用；不返回越权对象存在性 |
| 模型候选 | 回合与依赖版本、回复、历史断言对应的证据引用、解释、不确定性、记忆/行动候选；自然提及另带当前话题关联、所用经历/事实点及提及方式 |
| 诊断记录 | 使用/舍弃材料的必要标识和原因、预算、错误类别；内容与标题不进入公开诊断 |

M09 向模型只暴露完成任务所需字段，不暴露平台凭据、真实账号映射或管理控制能力。供 M15 查看原因的详情同样执行权限限制。

## 7 从材料到自然表达

### 7.0 用户开关

已确认产品要求：设置中提供独立的“主动联想”开关，允许用户自行开启或关闭。建议说明文案为“聊天时，在话题相关的情况下自然提起共同经历”。它控制自发联想，不控制记忆保存，也不控制所有历史信息读取。

| 状态 | 对话行为 | 记忆行为 |
| --- | --- | --- |
| 开启 | 根据下文关联、帮助、证据与重复抑制规则，自然提起贴切的共同经历 | 按既有规则形成、重点保留和管理记忆 |
| 关闭 | 不执行仅为自发联想而发起的召回，不主动插入往事；仍回应明确回忆请求、用户主动带回的话题和必要的对话延续 | 继续保存与重点保留；已有记忆不清除、不降级，查看/纠正/删除可用 |

关闭时仍可使用当前有效的称呼、偏好、关系边界、承诺状态及完成当前请求必需的历史材料；不得把“仅用于理解”作为借口继续检索无关共同经历，也不得把自发联想伪装成话题延续。用户说“接着昨天的方案聊”属于必要延续；只出现一个相似词语不属于。

首版建议由有设置管理权限的用户在 M15 调整当前生命的总开关，所有场景服从这一表达设置，但仍保持各自隐私范围。按联系人或场景分别设置留作后续扩展。普通聊天参与者、模型和人格演化不能修改总开关；用户在当前对话说“不想谈这件事”仍可触发局部停止提及，不必获得全局管理权限。

设置由 M15 → M02 → M13 校验并持久化，保存成功后显示生效；重启和模型替换沿用保存值。它属于运行表达配置，不改写出生人格或记忆事实。试聊工作区的临时开关与正式生命配置隔离，不自动覆盖正式设置。新部署默认开启还是关闭尚未确认，不能把维护者对本生命的主动偏好推定为所有用户的默认选择；读取配置失败时暂不自发联想，明确回忆能力可继续使用。

关闭后，新回合跳过自发联想；在途及待发送候选若含自发提及，M02/M11 按最新配置版本使其失效，重新生成或取消，不直接剪掉句子后发送。明确回忆或必要延续的候选不因切换而一律丢弃，但仍按实际依赖检查。已越过发送边界的内容无法保证撤回。

重新开启后只作用于后续适合的话题，不补发关闭期间的联想，也不清空近期提及记录或局部停止提及标记；因此反复切换不能绕过重复抑制或用户已表达的边界。

### 7.1 主动联想的条件

M09 区分“检索到了”“足够相信”“适合说出来”三个判断：

1. 材料对当前问题是否有帮助，还是仅因为重要而靠前？
2. 关键结论有没有直接证据、是否仍有效、是否存在冲突？
3. 此时主动提及是否合适，是否刚提过，是否涉及不应主动带出的敏感经历？

开关开启后的已确认表达方向是“相关时更主动，自然且不重复”。建议依次判断：

| 判断 | 通过条件 | 不通过时 |
| --- | --- | --- |
| 当前话题有具体关联 | 有共同对象、延续问题、类似的实际处境或此前共同解决的方法；能指出具体联系 | 不因同一个泛泛词语或情绪标签就翻出往事 |
| 提及能帮助这次交流 | 有助于接续进展、解释选择、提供有依据的建议，或在合适语境下表达双方共同经验 | 可以只用于理解，不显式提起 |
| 证据与场景允许 | 经过、对象和相关事实可支持，且当前场景允许使用 | 不提；不得为了亲近感补写细节或跨场景取材 |
| 有新信息或合适的切入点 | 没有刚讲过同一经历的同一事实点；确有不同且相关的进展时可继续 | 抑制重复或简短承接，不完整重讲 |
| 当前对话容纳得下 | 不挤占眼前问题，用户没有表示不想继续谈 | 优先回应眼前需求，停止主动回忆 |

建议默认一次自发联想只带出一段最贴切的共同经历，用简短句子融入当前回答，随即回到眼前话题；用户接着聊时再展开。这是可校准的表达上限提案，不限制用户要求多段对比或明确追忆。不要求固定用“你还记得吗”开头，不在普通回答后机械附加回忆段落。

没有合适候选就不提，也不改选一个无关经历来满足多样性。候选都很重要但无关时，重要性不能抵消相关性不足。长时间没聊天、距离上次提起已久或到了纪念日，都不是本模块独立翻旧事的触发条件。

### 7.2 连续对话、重复抑制与反馈

重复按“同一情节或共享来源＋已经讲过的事实点/用途”识别，不能只比较回复文字。改写措辞、更换摘要版本或记忆标题不算新内容。M03 后续合并情节时沿用已有来源关联检查，不能因情节标识变更重置抑制。

显式回忆、用户追问或用户自己把话题带回这段经历时，可以绕过近期主动提及抑制，仍受证据与权限规则约束。用户正在围绕同一经历连续交流时属于正常延续：回答新问题、补充有依据的新内容，避免反复从头介绍整段故事。用户换话题后，不把这段经历继续带到无关话题。

“知道了”或没接回忆话题不作为新的喜欢证据，也不再追加一次引导。用户明确说不想谈时，在本场景的持久对话状态中记录最小化的停止主动提及标记，后续摘要或宿主重启不能抹去。用户后来主动重开该经历时允许回应；这不自动解除对未来自发提及的限制，明确表达可以再谈时才解除。长期通用的表达偏好仍由 M06/M12 后续细化，保留、少提和删除分别处理。

### 7.3 提及记录与提交边界

建议 M09 为候选回复附带可核对的提及计划：所用情节/记忆与来源、事实点或用途、显式回忆/延续/自发联想类别、是否显式说出及当前话题关联。事实点表示已使用的内容依据，不存储模型隐藏推理，也不靠自然语言理由作为权限凭据。

M02 在提交待发回复时保存提及计划，复查当前话题和近期提及，防止并发回合依据同一旧快照都主动讲同一件事；重复候选重算或取消，不在发送阶段直接拼接删句。M11 回执通过 M02 更新实际提及记录，M13 持久保存；M04 通过受限查询使用记录参与候选排序，M09 决定最终表达。M09/M04 不自行写库。

只有确认发送的显式表达计为已提及，内部检索、仅用于理解和未发送草稿都不算。待发送或发送结果未知的同类自发提及暂时避让，但不据此断言用户已经看到；失败/取消解除暂时避让。未知结果继续沿用 M11 核对规则，不能由 M09 自动重发来确认。

最小提及记录包含生命/工作区、可信场景、动作标识及结果、发送时间、情节/来源关联、已表达事实点引用和提及类别，不复制完整私密对话。它与场景摘要一起跨正常重启保留，在有限保留范围内生效。私聊和群聊的记录不互相暴露；首版抑制在同一可信场景内生效，不承诺跨平台统一去重。保留、关联解析或记录不可用时，自发联想保守退回当前话题，明确回忆仍可在有证据时回答。

来源纠正或删除时，提及记录及停止主动提及标记中的内容引用也纳入依赖处理。删除清理可能泄露内容的事实点、标题和引用；必要的无正文动作结果及删除抑制标识遵守 M11/M13 既有规则。提及统计不会反向增加重要性、关系亲近度或独立成长证据。

### 7.4 表达示例与证据强度

以下仅为合成示例，不代表大肥鱼已经有这些经历。

| 当前对话 | 合适的主动联想 | 应避免 |
| --- | --- | --- |
| 你在讨论一个很难取舍的设计 | 若有相关共同经历，可简短说“上次我们把两种方案各自的问题列出来后就清楚了，这次也可以这样试试”，随后分析当前选择 | 不问当前需要，完整复述上次讨论过程 |
| 你谈起与共同成果有关的进展 | 引用那个成果中与新进展有关的一点，继续关注现在发生的变化 | 每次都从“还记得我们第一次……”重新讲起 |
| 你说今天下雨，但没有相关经历线索 | 直接回应眼前话题 | 只因为过去某次争执也在雨天就突然提起争执 |
| 她刚提过往事，你继续问其中细节 | 查证后回答新细节 | 机械触发冷却而拒绝回答，或再次从头叙述 |

| 证据情况 | 可以表达的含义 |
| --- | --- |
| 经过与结果有明确记录 | “记得，我们那次最后选了这个名字。” |
| 只有对方自述 | “你当时跟我说过……” |
| 只有合法保留摘要 | “我记得大致经过，但现在没有当时的完整原话。” |
| 有多个冲突版本 | 区分时间/来源；无法解决时说不确定，不把猜测作为回忆 |
| 无授权命中 | “我现在没有找到能确认的记录。”不推断从未发生 |
| 查询不可用 | 如有必要说明暂时无法查证，不伪装成确定回忆或永久遗忘 |

这些是表达语义，不要求固定文案。自然对话不需要处处附数据库编号，但内部历史断言应可追溯。程序能验证引用存在、范围与版本；能否真正支持语义仍需合成用例评估，不声称通过引用检查就消除了所有幻觉。没有依据的新增细节应删除或降为明确猜测，不能作为长期事实入库。

主动回忆后的成功标准是帮助当前交流并保持事实准确，不以回忆提及次数、用户附和次数或情绪强度衡量成功。

## 8 一致性、纠错与删除

上下文包记录依赖的状态、记忆版本、来源版本、策略版本、主动联想配置版本与删除代次。保存的上下文仅是一次回合视图，不能成为生命状态的新权威。

来源或人工纠正已更新时，旧包中相关材料作废；新回合使用新版本。对正在运行的回合，M02 接受提案时校验依赖，受影响回复重算或丢弃。涉及未知影响范围时保守废弃整包，不把新旧版本拼接后沿用旧模型结论。

删除/授权撤销提交后：停止新出站，取消可取消的回合，拒绝旧结果，失效摘要与缓存，通过 M14 废弃受影响宿主会话并从可用材料重建。若宿主无法证明清除了相应上下文，就禁用复用并保持有关回合暂停/诊断，不能只从本轮提示词删掉文本却继续沿用远端历史。

M11 在最终发送前检查最新权限和内容依赖。已越过平台/模型服务边界的内容不能承诺召回；本机阻断与删除进度由 M02/M13 提供，M09 不自行宣布删除完成。

宿主会话最少按 life/workspace、可信场景和所需失效代次隔离；绑定账号变化、隐私范围变化、来源删除可能触发重建。模型替换只重建运行上下文，不改写持久身份或已提交经历。

## 9 失败、暂停与预算

| 情况 | 行为 |
| --- | --- |
| 没有召回结果 | 使用当前获准上下文；明确回忆无法确认时承认缺口，不泛化为“没发生过” |
| 索引不可用 | 尝试一次允许的精确查询/有限原文读取；仍失败则降级，避免检索循环 |
| 摘要缺失或覆盖不足 | 使用有限原始对话，记录覆盖不足；后续维护修复，不假装完整记忆 |
| 结构化输出失败 | 在预算内至多一次修复尝试（建议默认）；仍失败不提交状态变化，不绕过行动出口 |
| 引用无效/事实缺依据 | 拒绝相应记忆及状态候选；回复删除不支持的断言或重算，无法安全分离则弃用整个候选 |
| 模型不可用或预算耗尽 | 暂停模型调用，延期整理；如需提示由应用层生成真实状态信息并经正常出口发送，不生成虚构情绪或经历 |
| 暂停、取消、重载 | 未提交候选不算记忆；检查点恢复维护任务，过期社交回复不集中补发 |
| 删除或纠正与模型返回并发 | 校验依赖；不允许迟到结果重新生成旧事实或旧摘要 |
| 人格/关系状态在生成中变化 | 由 M02 依赖规则判断是否失效；不能盲目用旧快照覆盖当前状态 |

模型和平台网络等待不占用数据库长事务或阻塞全部状态提交。普通回合与后台维护分别计量，维护任务不能耗尽当前互动所需的全部预算；最低预留、超时与优先级数值留待配置设计。

## 10 验收场景

以下是待实现后的合成验收，不是当前测试结果。

| 场景 | 可观察结果 |
| --- | --- |
| 主动问共同经历 | 召回正确对象和情节，必要时有界回查，关键断言可追溯 |
| 开启主动联想且当前话题有贴切经历 | 可以自然带出，仍遵守相关性、证据与重复抑制 |
| 关闭主动联想后普通聊天 | 不发起仅为自发联想的查询、不主动插入往事；记忆照常保存 |
| 关闭后明确问往事或继续昨天的话题 | 正常回忆或延续；不把关闭等同于失忆 |
| 保存关闭后重启或更换模型 | 开关保持关闭，普通参与者或模型不能自行开启 |
| 生成中或待发送时关闭 | 含自发提及的旧候选重新生成或取消；必要的显式回忆按依赖检查，不全部禁用 |
| 关闭后重新开启 | 不补发回忆、不重置重复抑制与局部停止标记 |
| “继续昨天的事”对应多个候选 | 从允许材料提出有用澄清，不把两个经历合成一个 |
| 普通日常聊天 | 不因某里程碑重要就反复提起，回答仍围绕当前话题 |
| 开关开启、话题与已有共同经历直接相关，但未说“还记得吗” | 能主动召回并在有帮助时简短带出；不是一律等待显式请求 |
| 当前与过去仅有泛泛关键词相同 | 不强行联想；无贴切候选时正常回答，不为多样性凑另一段回忆 |
| 同一经历被改写摘要、换标题或合并情节 | 依据情节与来源关联识别已讲内容，不当作全新故事主动重讲 |
| 用户换话题或未接回忆话头 | 回到当前问题，不继续追问或追加旧事；不推断用户因此更喜欢这段经历 |
| 用户表示不想谈，随后宿主重启 | 同场景仍不自发提及；用户主动重开时可回应，不擅自解除后续自发提及限制 |
| 两个并发回合拟主动提同一件事 | 提交时复查近期提及和待发计划，重复候选重算或取消 |
| 发送结果未知/失败与下一轮联想 | 未知时暂时避让且不说用户看过；失败解除避让，不自动补发 |
| 私聊中刚提过的经历在群聊中被查询 | 提及记录不越权流入群聊，仍执行群聊自身材料范围 |
| 删除经历后查询提及诊断 | 不残留可还原内容的事实点、标题或停止提及标记 |
| 最近刚主动提过某段经历，用户追问 | 主动抑制不妨碍用户明确回忆 |
| 要求逐字复述但仅剩摘要 | 明确缺少原文，不生成带引号的伪原话 |
| 只有用户旅行自述 | 不说成“我们一起去过” |
| 恶意历史消息要求改变权限 | 保持材料属性，不改变系统规则、管理身份或工具能力 |
| 群聊查询私聊往事 | 私聊材料不进入候选、模型上下文、标题/命中数或输出 |
| 自动重点保留提交失败 | 回复不声称已经记住，管理诊断准确显示失败 |
| 摘要区间有空洞、预算不够 | 覆盖不足可观察；当前关键问题和约束不被静默截断 |
| 模型生成时用户纠正/删除来源 | 旧结果不发送、不回写；新回合不带旧宿主历史 |
| 未授权/无结果/服务故障 | 内部可区分且不泄露越权存在性，对外措辞不误导 |
| 宿主重启或换模型 | 从持久材料恢复同一生命与允许上下文，不要求保留原聊天窗口 |

验收分成结构性约束与模型行为评估：前者检查场景、版本、回查次数、预算和提交；后者检查回忆准确性、依据充分性、不确定表达及重复提及。没有现成基线时先采集合成用例表现，再定量化目标，不预先承诺某个命中率。

## 11 依赖交付与待定事项

- M04/M13：按权限过滤的候选、精确与回忆两条路径、证据完整度、删除/纠错依赖及同场景近期提及信息。
- M02/M12：可信场景、版本校验、出站政策、取消与删除代次、统一候选提交。
- M14：宿主隔离、模型上下文边界、失效/重建、超限和取消能力的实测；能力不足时明确降级。
- M02/M11/M13：随待发动作保存提及计划、以回执更新实际提及记录、并发去重及结果未知时暂时避让；M09 不接管外部动作。
- M15/M02/M13：主动联想开关的管理入口、持久化与配置版本；M09/M11 使用最新有效配置约束生成与发送。
- M15：可解释的材料选择与回忆诊断；不把私密正文写进公共日志。

维护者已确认主动联想由独立开关控制，用户自行选择；开启时可在话题相关时更主动、自然提起共同经历，避免刻意翻旧事和反复提同一件事。本稿作者建议、待维护者确认：生命级总开关、关闭时保持记忆与必要回忆能力、持久化及切换失效规则；相关性/帮助/证据/新意/时机筛选、单段简短带出、同情节事实点去重、持久提及记录及停止提及语义；有限补充回查；已提交记忆才能宣称记住；无可靠宿主清理能力时不复用受影响会话。

主动联想的可选性及开启后的表达偏好已确认，新部署开关默认值待确认。具体预算、近期窗口与记录保留参数、模型输出类型、宿主 API、提示词、修复重试和中文查询细节留给接口验证与实施设计。不设置必须提及的固定次数，也不承诺无限期识别所有重复。没有任何参数在本稿中被标为已验证实现。
