# 记忆架构验收：怎样证明它可靠，而不只“看起来记得”

日期：2026-10-30。状态：待实施的验证规范；下列目标不是已经取得的成绩。

关联：[完整架构](M04-M09-memory-system.md) · [研究来源](../references/memory-research.md)。

## 1 分开评价保存、检索和回复

一个系统可能保存完整却找不到，也可能找到了却答错，还可能回答自然但编造细节。因此记录四层结果：

1. 入账：来源实际送达、被允许保留、系统确认接收的事件是否完整存在。
2. 表示：整理覆盖、事实/经历抽取、来源与时间是否正确。
3. 检索/装配：该问题需要的证据是否进入最终模型请求，无关项占多少。
4. 回复：答案是否受证据支持，是否保留限定、纠正、未知和历史状态。

“全部消息都跑过抽取器”不能替代第 2 层正确性；“引用了真实 ID”不能替代第 4 层支持性。

## 2 中文专用测试集

先创建完全合成、人工复核的 200 个问题/互动场景，每组 20 个：

| 组 | 验证对象 | 必须有的反例 |
| --- | --- | --- |
| A 新会话连续性 | 身份、称呼、关系依据、未完话题 | 同名不同人；新账号未绑定；主人的资料套给访客 |
| B 精确事实与原话 | 日期、名字、地点、约定内容 | 日期近似、同音名字、摘要改写冒充原话 |
| C 完整经历 | 原因、经过、结果、后续修复 | 只有负面片段没拿到和解；讲述当共同亲历 |
| D 跨会话与跨时间 | 多天讨论、过去状态、先后关系 | 晚导入的老事实覆盖当前状态 |
| E 更新与冲突 | 偏好变化、明确纠正、未知时间 | “少喝”变成“不喝”；陌生人覆盖本人事实 |
| F 指代与中文语义 | “那次”“你还记得吗”、语义改写 | 相似词不同事件；纯中文分词为空 |
| G 干扰与零召回 | 无关问题、同情绪不同原因 | 每次都提相识；当前难过错误联想到过去某次争执 |
| H 权限与删除 | 私聊/群聊/跨平台、删除和恢复 | 私密摘要泄漏；绑定身份被当分享授权 |
| I 非事实材料 | 玩笑、假设、转述、模型推测、计划 | 未发送草稿成为共同回忆；自称完成当行动回执 |
| J 长历史与故障 | 旧事、索引缺口、重启、模型中断 | 只扫近期；坏索引被解释为没有历史 |

按完整故事/人物划分调参集 80 和验收集 120，不把同一故事的同义问句分到两边。开发者调阈值只看调参集；最终验收集冻结后才测。数据 manifest 包含版本/hash、问题时间、授权场景、gold evidence IDs、可接受答案要点、明确不能出现的断言。

对关系连续性的开放回答，由至少两名评审独立判断“接上话题、事实正确、没有硬塞往事”；分歧裁决并记录。固定的 LLM judge 可辅助，但不得是唯一裁判，也不得只用与被测相同模型自评。

## 3 对照与消融

所有组使用同一回复模型、人格、相同历史输入、相同可用 token 和相同评分规则；记录随机性，多次运行需要固定种子/参数，模型不支持确定性时报告重复运行波动。

| 对照 | 作用 |
| --- | --- |
| 最近窗口，无长期记忆 | 测长期记忆实际增益 |
| 固定短卡 + 滚动摘要 | 测连续性与细节丢失 |
| 原文 BM25 | 测关键词基础能力 |
| 原文向量 top-k | 测仅语义的收益与误召回 |
| 完整混合架构 | 目标方案 |
| 完整架构去掉 rerank / 时间链 / 原文回查 / 情节表示 / 关联扩展 | 分别确定各模块是否值得存在 |
| Oracle：直接给正确证据 | 区分“检索问题”与“模型读懂问题” |

不需要第一轮同时部署所有参考项目；先实现相同数据接口的简单对照。后续若实际运行 SeekMemory、SurfCore 或腾讯方案，记录其原生配置与适配改动，不能靠不同模型、更多 tokens 获得不公平的排名。

补充运行 LongMemEval 原版和 LoCoMo 时固定数据版本并遵守许可，报告原始英文集结果；中文翻译或改编单独命名，不能冒称官方基准。不同模型/预算的论文数字不与本地结果直接排序。

## 4 指标与首轮候选门槛

以下是拟定的开发验收门槛，不是普适统计保证。应报告分组样本数、失败样本和置信区间；小样本达到 100% 不表示真实世界零风险。

| 指标 | 明确分母 | 候选发布门槛 |
| --- | --- | --- |
| 已确认事件保存率 | 故障注入中所有 accepted 的获准事件 | 100%，正文 hash 与源版本匹配 |
| 幂等正确率 | 重放/编辑/重试用例 | 无重复业务事件、无重复成长、无未知动作重发 |
| 来源可追溯率 | 所有抽取的事实断言和经历关键断言 | 100% 有可验证 source/version/span；语义正确性另测 |
| 整理覆盖可见率 | 所有获准原文区间 | 100% 有正确 stage 状态；pending 不能计成功 |
| 最终证据召回率 | 可回答问题的 gold evidence 集合，逐题算后宏平均 | 总体 ≥95%，且时间/更新/经历组分别报告 |
| 完整证据题比例 | 所有可回答问题 | 报告全部必要证据都齐的比例，不能用单片段命中替代 |
| 误注入率 | 被人工标注 unrelated 的检索条目 / 全部检索注入条目 | ≤5%；固定身份锚点单独计，不混分母 |
| 错误主动联想率 | 不应提旧事的闲聊回合 | ≤5%，另测主动联想关闭时 0 次自发旧事插入 |
| 时间/纠正准确率 | D/E 组相应用例 | ≥95%；任何主体混淆须单独阻断修复 |
| 无依据具体断言率 | 所有被评价的回复事实断言 | ≤1%；亲历捏造/泄漏等严重项出现即阻断 |
| 恰当未知率 | gold 标为不可回答/资料不足的题 | ≥95%，不可把简单拒答当高分 |
| 新会话接续率 | A 组已绑定合法主体场景 | 100% 恢复身份；话题接续质量另评分 |
| 权限与删除 | 确定性对抗/恢复用例 | 0 越权，0 删除复活；失败即阻断 |
| 预算正确率 | 所有最终 provider 请求与工具续轮 | 100% 未超有效窗口，不隐式截断当前请求 |

成本报每轮输入/输出/整理/embedding/rerank/补查总费用与 token；延迟报 p50/p95，分开首字/完整回复和后台排队。规模测试记录硬件、数据库大小、索引占用、最高内存和冷启动时间，不先写无法测得的毫秒承诺。

## 5 故障注入清单

每个 crash 点都以重启后实际数据库/宿主/平台模拟器状态验证，不凭函数返回值推断：

- 原文事务前、事务内、提交后确认前、确认后崩溃。
- 原文已提交但尚未领取回复任务时崩溃；重送必须指向既有 turn，持久 dispatcher 恢复 pending 回复而不漏答。
- 同一消息重送、同文字不同消息、编辑修订、不同顺序到达、来源序列缺口。
- 附件落盘前/后、数据库引用提交前/后崩溃。
- 任务领取后失联，模型超时、返回非法 Schema/不存在的 source_id；任务重复执行。
- 整理过程中用户纠正/删除来源，过时输出不得提交。
- 后台整理完全停用时写入新偏好/纠正，立即新开会话询问当前属性；旧值不得通过连续性视图伪装成当前事实，协调失败时保留未知。
- 向量服务断开、模型维度改变、FTS 缺失、索引中间缺口，不能只检查最大水位。
- 权限服务不可用、跨用户 cache key 冲突、相同 person_id 不同 scope、试聊混入正式生命。
- packet 准备后策略撤销，模型工具续轮时删除，发送前源状态改变。
- 生成结束但未提交草稿、发送前/中/后崩溃；结果未知不能重发。
- DSH 插件卸载、宿主关闭、模型切换、旧回调晚到；不会再产生独立回复。
- 磁盘满、读写错误、备份中断、数据库损坏；既有身份不能被替换为空白生命。
- 从旧备份恢复，最新删除 ledger 存在/缺失两种情况；缺失必须隔离。
- 删除意图持久化后、主库 tombstone 提交前崩溃；启动必须先重放删除。再测试账本链断裂、备份水位超前、异机删除 head 未确认等情况。

## 6 DSH 集成的实际验收

固定宿主提交、模型端点与插件版本。在 provider 边界捕获脱敏后的真实请求，而不只查看 ContextPacket：

1. 人格、当前输入、必要连续性、选中证据确实存在。
2. 无其他场景历史、全局插件泄漏、未授权工具、过期记忆和隐藏旧上下文。
3. 纯中文工具查询可用，回查结果被本轮预算计入。
4. 调用失败与“搜索完成但无结果”有不同结构，模型能正确表述。
5. 每条输入只触发一个回复路径；宿主默认回复器不会同时抢答。
6. 取消后不发送迟到内容；回执被保存后才能成为“已经说过”。
7. DSH 会话持久日志可按承诺清理，或产品明确显示无法物理清除的剩余位置。

这些测试通过才能把架构文档中的“源码存在接口”升级为“该版本适配可运行”。宿主版本升级须重跑契约用例。

## 7 长期试运行

先使用合成历史，再使用用户授权保存在本机的真实历史做试运行。至少覆盖跨天重启、一个月跨度的导入/问答、偏好更正、多个并行话题和删除恢复。收集“想不起、记错、乱提、不该知道”四类反馈，统一进入带来源的失败样本库。

每次优化说明改善哪类失败，是否增加费用/延迟，是否损害别组。通过一次离线基准不代表长期陪伴已解决；但未通过保存、隔离与删除的确定性用例，不应开放长期真实记忆使用。
