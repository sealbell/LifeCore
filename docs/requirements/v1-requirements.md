# 生命核心第一版需求单

版本：0.1 讨论稿 · 日期：2026-10-30 · 实现状态：全部未开始

本需求单覆盖生命核心 M01–M15，用于范围确认、模块讨论、开发拆分和验收。这里的“第一版”指第一个可供维护者试用的完整项目版本，不是已有架构文档名中的 V1，也不是仅完成记忆存储的工程演示。

阅读顺序：[架构与数据流图](../architecture/v1-data-flow.md) → 本文模块清单 → 待决事项 → 联合验收。依据：[架构基线](../architecture/v1.md)、[分层契约](../architecture/layers-and-calls.md)、[出生流程](../architecture/modules/M01-birth-flow.md)、[完整记忆方案](../architecture/modules/M04-M09-memory-system.md)。

## 1 如何记录和开会

- 每项需求有稳定编号，例如 V1-M04-03。讨论、Issue、提交和验收报告均引用编号，删减需求时保留编号和决定记录。
- **P0：建议首版发布必需。P1：首版候选，会议纳入后才成为发布门槛。P2：后续版本。** 优先级不是开发顺序。
- **C：此前明确确认的目标/流程；B：既有架构方向，具体机制仍需确认；N：本次提出的首版细化。** C 不表示这行的工程验收已经执行。
- 本文所有需求初始状态为“待范围确认”，实现状态均为“未开始”。确认范围后才进入“待设计 → 可开发 → 开发中 → 待验收 → 完成”；每次改变状态填写证据链接。
- 本文的具体完成条件是验收提案，不自动冻结技术选型。SQLite、TypeScript、向量后端、模型、DSH 安装方式均有独立技术决策项。
- M 编号是职责，不是 15 个服务或 15 个模型。每行的主责是所在模块；涉及其他模块时由共同验收覆盖。
- 若一项 P0 无法完成，应修复，或在会议记录中明确缩减版本范围；不能仅在说明里写“暂不支持”却仍声称首版需求全部完成。

## 2 第一版建议达到的体验

维护者可以创建并试聊“大肥鱼”，确认出生；在一个受控文字聊天入口与她持续交流。她能恢复身份和关系、记住共同经历、更新事实、体现可解释的短期状态与受约束的成长，保存未完约定；新会话、插件重载和宿主重启不会清空这些状态。维护者能查看依据、纠正、删除、暂停、备份和恢复。

建议验收入口是 **DSH 开发/管理入口 + 一个受控 QQ 私聊**；前者用于诊断和出生试聊，后者用于实际互动。QQ、QQ群、B站属于同一生命的不同场景。首版是否增加群聊/B站由 D01/D02 决定；未纳入的平台也必须遵守预留接口和隔离测试，不能创建第二份生命状态。

## 4 M01 身份与出生

主责：定义出生材料与身份。输入：维护者设定、预设、确认版本和导入选择。输出：出生/管理修订候选。依赖：M02/M04/M06/M07/M12/M13/M14/M15。数据由 M02 提交至 M13。

| 编号 | 等级/依据 | 首版需求与完成条件 |
| --- | --- | --- |
| V1-M01-01 | P0/C | 自然语言形成可编辑草案；原文、整理解释和新增建议分别标注，删除的建议不会进入最终档案。 |
| V1-M01-02 | P0/C | 提供两个可试用预设和空白起点；选择预设只建立草案，不生成第二个正式生命；正式文案见 D03。 |
| V1-M01-03 | P0/C | 隔离试聊可反复修改/继续；试聊不会自动修改正式记忆、关系、情绪或人格。 |
| V1-M01-04 | P0/C | 记忆按选中内容整理并确认导入；关系默认不导入，单独确认；人格修改后原关系仍保留，建议变化待复核。 |
| V1-M01-05 | P0/C | 出生保存用户最终确认的原版本，不二次生成替代档案；重复点击/断网重试仅产生一次出生；出生原稿与当前人格分开。 |

首版外：多生命切换。会议问题：两个预设的文案、试聊保留期限与正式初始设定（D03/D08）。

## 5 M02 生命协调器

主责：组织用例、验证和提交，不替各模块决定算法。输入：入站、管理请求、模型候选、时钟唤醒、回执。输出：提交结果、持久任务、待执行动作。依赖：M03/M12/M13/M14 及对应领域模块。

| 编号 | 等级/依据 | 首版需求与完成条件 |
| --- | --- | --- |
| V1-M02-01 | P0/B | 原始事件、整理待办和需回复时的 turn/reply job 一起提交；提交后未领取任务即崩溃，重启仍能继续，不静默漏答。 |
| V1-M02-02 | P0/B | 变更带依赖版本/幂等键；重复处理无重复效果，已过期或已删除来源的结果不得覆盖新状态。 |
| V1-M02-03 | P0/N | 同一对话顺序明确，不同场景可并发计算；网络等待不持有长写事务；队列积压、租约和失败可查看。 |
| V1-M02-04 | P0/B | running/paused/recovering/stopped 等运行状态可核验；暂停后不发新执行许可，迟到生成结果不能越过取消。 |
| V1-M02-05 | P0/B | 管理操作、模型输出、定时唤醒与发送回执通过各自可信入口；失败返回阶段与原因，不显示虚假的保存/发送成功。 |

首版外：多机主从调度。会议问题：并发、超时和重试资源预算（D10）。

## 6 M03 事件与经历

主责：定义事件事实和情节成员。输入：接入材料、管理修订和行动结果。输出：规范事件、去重判定、情节关系。依赖：M02/M06/M10/M11/M12/M13。

| 编号 | 等级/依据 | 首版需求与完成条件 |
| --- | --- | --- |
| V1-M03-01 | P0/B | 保存事件 ID、来源 ID/修订、主体、场景、发生/接收时间及获准原文；同文字不同消息不被误去重。 |
| V1-M03-02 | P0/C | 来源陈述、直接观察、解释、意图、结果分类；“我已经发了”这句文字不能替代平台回执。 |
| V1-M03-03 | P0/B | 平台重送、模型结果/宿主重复采集、旧记录导入可关联去重；编辑/纠正保留修订关系，不悄悄覆盖历史。 |
| V1-M03-04 | P0/B | 支持跨轮情节和独立事件实例；同词/同日不自动合并成同一次经历；能从情节定位原始成员。 |
| V1-M03-05 | P0/N | 晚到事件保留实际时间；缺附件、缺历史、仅转写均显式标识；可删除载荷不因事件壳保留而继续暴露。 |

首版外：复杂媒体自动理解，除非 D11 纳入。会议问题：平台漏消息/重放能力和原文范围（D01/D08/D11）。

## 7 M04 记忆

主责：记忆表示、重要性、冲突与召回规则。输入：原始事件、合法候选、可信查询范围。输出：记忆候选和带证据的检索结果。依赖：M02/M03/M09/M12/M13；不另管承诺执行状态。

| 编号 | 等级/依据 | 首版需求与完成条件 |
| --- | --- | --- |
| V1-M04-01 | P0/C | 共同经历和重要事情可保留并回查原文；摘要/事实均有来源版本；不把被讲述的旅行写成双方共同亲历。 |
| V1-M04-02 | P0/C | 自动判断重点保留并记录理由，不逐条要求用户批准；用户能查看、纠正、降级或删除；重要不意味着每轮必须提及。 |
| V1-M04-03 | P0/N | 文字精确查询与中文同义回忆均有验证；相关性先于重要度，无关/无可靠结果允许不召回；查询故障与零命中分开。 |
| V1-M04-04 | P0/B | 当前与历史事实分开，纠正和争议可追踪；刚收到新变化时旧当前值暂停使用；时间不明不能自动按入库先后覆盖。 |
| V1-M04-05 | P0/N | 每个获准区间有整理覆盖状态，失败可重做；删除/更正使相关摘要、索引和连续性视图失效；原文不因暂时未提炼到重点而消失。 |

首版外：无限量全历史注入、没有评测依据的复杂图系统。会议问题：保留策略、语义模型/成本和效果门槛（D08/D10/D12）。详见记忆专项文档；既有“全文优先”是开发阶段，不等于中文语义能力可用空实现交付。

## 8 M05 情绪与心境

主责：短期情绪、心境及变化理由。输入：已验证事件评价、旧状态、显式时间。输出：状态变化候选与可披露表达提示。依赖：M02/M03/M09/M12/M13。

| 编号 | 等级/依据 | 首版需求与完成条件 |
| --- | --- | --- |
| V1-M05-01 | P0/B | 即时情绪与较慢变化的心境分开持久化；重启后恢复，不每次回到虚构初始状态。 |
| V1-M05-02 | P0/B | 变化有源事件、评价和规则版本；同一事件重复处理不重复放大状态。 |
| V1-M05-03 | P0/N | 衰减使用显式时间，固定输入可重放；时钟回拨不反向增长；离线不产生新经历，离线是否衰减由 D04 决定。 |
| V1-M05-04 | P0/B | M09 可获得授权范围内的当前状态；短期难过不直接改核心人格、所有人的关系或权限。 |
| V1-M05-05 | P0/N | 维护者能看见触发原因与调整记录；人为修正标为管理操作；维度、上下限及表达强度在 D04 冻结后才验收。 |

首版外：复杂生理模拟。会议问题：状态维度、衰减与表达程度（D04）；不预先把某套情绪数值当已确认需求。

## 9 M06 关系

主责：人物身份绑定、关系状态与依据。输入：可信账号、出生导入、经历与修订。输出：对象映射、关系变化候选及受限摘要。依赖：M01/M02/M03/M12/M13。

| 编号 | 等级/依据 | 首版需求与完成条件 |
| --- | --- | --- |
| V1-M06-01 | P0/B | 平台账号与 person_id 稳定关联；改昵称不变陌生人，同名不同人不合并；跨平台绑定可核验/撤销。 |
| V1-M06-02 | P0/B | 关系至少可分别表达熟悉、信任、亲近和边界，不以单一好感度替代；具体字段/尺度按 D05 确认。 |
| V1-M06-03 | P0/B | 变化引用独立经历；误解与和解追加可追溯记录；对一个人的变化不自动影响所有对象。 |
| V1-M06-04 | P0/C | 新会话能恢复当前对象的关系依据；身份绑定和亲近程度不增加私密读取、管理或工具权限。 |
| V1-M06-05 | P0/N | 人工纠正、绑定撤销和证据删除可触发受影响状态复核；不能保留已删除来源的可识别理由。 |

首版外：仅靠模型推测现实身份。会议问题：身份绑定方法、关系维度、删除后的校正方式（D05）。

## 10 M07 人格演化

主责：当前人格、演化限制和历史。输入：M01 初始人格、独立证据、规则与旧版本。输出：接受/拒绝的修订及当前快照。依赖：M01/M02/M03/M06/M12/M13。

| 编号 | 等级/依据 | 首版需求与完成条件 |
| --- | --- | --- |
| V1-M07-01 | P0/C | 出生原稿与当前人格独立保留；模型切换不重写出生；人工编辑记录为管理修订。 |
| V1-M07-02 | P0/B | 独立经历可支持或反对变化；转发、刷屏、自我复述和反思不能制造多份成长证据。 |
| V1-M07-03 | P0/N | 提供可运行的受约束演化链路：候选 → 证据核验 → 单次/周期预算 → 新版本或拒绝理由；不足证据时保持不变。 |
| V1-M07-04 | P0/B | 偏好/习惯与核心倾向有不同变化规则；重大事件可形成强情绪和重要记忆，但不能任意越过预算；哪些维度首版自动变化由 D06 决定。 |
| V1-M07-05 | P0/N | 可查看变化前后和允许披露的依据；证据删除后复核当前版本，历史修订可审计但不能泄露已删除正文；成长不能改隐私策略。 |

首版外：无边界自我修改。会议问题：自动演化维度、默认开关、证据门槛和预算（D06）。只实现人格读写接口不算完成 M07；至少要有可执行规则和固定输入回归，线上启用范围另定。

## 11 M08 自主活动与承诺

主责：目标、承诺、计划和候选活动。输入：经历、状态、时间与实际行动结果。输出：计划变更及行动候选。依赖：M02/M03/M09/M11/M12/M13/M14。

| 编号 | 等级/依据 | 首版需求与完成条件 |
| --- | --- | --- |
| V1-M08-01 | P0/B | 承诺有主体、内容、来源、期限/未知时间和状态；提出、接受、进行、完成、取消/失败可以区分。 |
