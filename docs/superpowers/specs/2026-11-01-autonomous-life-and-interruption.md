# LifeCore 自主生活、并行活动与中断恢复修订

日期：2026-11-01。状态：依据用户本轮明确目标形成的设计修订；不是已实现能力，也不是账号操作授权。

当前完整评审入口：[项目设计与开发前核对稿](2026-11-01-lifecore-complete-design.md)。本文继续作为自主活动与中断恢复的专项依据，整合稿补充工作任务、记忆、费用与后台体验，仍待维护者核对。

关联：[生产架构](2026-11-01-production-plugin-architecture.md)。本文件优先于该稿中“官方QQ为主入口、B站仅留接口、视频理解不纳入、首版以聊天为主”的范围建议。事务、隐私、身份、删除和恢复原则继续适用。

## 1 产品目标与具体体验

大肥鱼是有持续身份、兴趣、关系和活动轨迹的自主角色。聊天是她的一种活动；没人发消息时，她也能在已授权范围内选择事情做。用户明确希望：主动发QQ、改头像、发说说、浏览抖音/B站、被消息打断、聊完继续，以及边做事边交流当前见闻。

这改变了产品主循环：不能继续把“收到消息→调用模型→回复”当完整生命运行时，也不能用每隔几分钟发一句话代替自主生活。必须有真正可暂停/恢复的活动、实际环境观察和执行结果。

目标场景（产品示例，不是已发生的行为）：

1. 她依据兴趣、近期经历、作息和预算，选择一个B站视频。
2. 播放到某个位置，已经处理了对应字幕/音频/画面，记录看到什么和自己的解释。
3. 用户发QQ；接收立即入账，聊天获得优先级。简短交流可与观看并行；需要专心时保存检查点并暂停视频。
4. 她可以据真实活动快照说“刚看到这个片段”，分享链接、时间点和自己的短评。不能仅因网页标题就声称看懂整部视频。
5. 聊天告一段落后，调度器重新检查活动、页面和意愿；仍适合继续时恢复同一个视频和进度，而非重新搜一个假装续看。
6. 她也可以决定不继续，但要把原活动标记为放弃/延期并保存原因，不遗失未完成状态。

“像人一样”的工程验收对应连续身份、主动选择、注意力切换、可追溯经历和行为一致性。

## 2 技术路线修订

| 部分 | 本次决定 | 原因与边界 |
| --- | --- | --- |
| QQ主身份 | 大肥鱼专属普通QQ账号；NapCat作为首个真机验证目标，SnowLuma作为可替换适配器 | 用户要求普通账号头像、空间说说与社交生活；官方机器人不能当普通QQ空间账号使用 |
| 官方QQ机器人 | 保留为可选交流入口 | 不能继续作为满足全部目标的唯一默认入口 |
| 微信 | 保留ClawBot独立入口 | 与其他入口共享生命；不声称接管普通微信好友/群/朋友圈 |
| 活动运行时 | 自研 M08 ActivityEngine + M02 Attention/Resource Scheduler | SeekMemory 的整理/主动回复不能直接替代持续浏览、暂停和续做 |
| 浏览与视频控制 | M10 受控浏览器适配器，首选 Playwright + 独立浏览器配置目录 | 复用浏览器自动化组件；自己实现站点识别、播放器读回、分页/推荐流游标和恢复 |
| 视频感知 | 平台可访问字幕、获准音频转写、按需画面采样，经M09模型服务理解 | 播放、采集、理解和记忆分别记录；缺一路不能假装有完整理解 |
| 语音转写 | faster-whisper作为本地ASR集成候选；与字幕走统一Observation契约 | 仍需锁模型/运行包并测CPU/GPU资源；不是安装后自动获得网页音频 |
| 人格、记忆、事务 | 继续使用前稿的托管Python单权威方案 | 多活动不需要多个生命、多个写入者或各自独立的记忆库 |

NapCat/SnowLuma均有许可与分发条件，沿用[平台调研](../../architecture/references/2026-11-01-platform-research.md)的限制，不将第三方运行时默认打包或重新许可。这里因产品能力选择普通账号路线，不等于已经完成许可/账号/稳定性验收。

B站和抖音都属于目标范围；先完成B站纵向闭环，再完成抖音站点适配，是实施顺序，不是把抖音从最终范围删掉。站点登录态、播放器结构和风控是必须做的实机门槛；遇到验证码、授权失败或页面能力缺失进入blocked，不自动绕过。

## 3 一个生命，多条活动，有限注意力

区分四个概念：

- **活动 Activity**：看某视频、准备一条说说、聊天、整理日记等持续目标。
- **步骤 Step**：读一次字幕、检查页面、生成一段回应、提交一次发送等有界操作。
- **注意力 Attention**：决定哪个活动获得下一次模型计算和响应优先级。
- **资源 Resource**：模型槽位、浏览器标签页控制权、音频采集、平台发送额度；只有冲突步骤互斥。

默认资源预算：社交接收常驻；最多一个主动视频/音频感知活动；模型最多两个并发任务，至少为实时交流保留优先调度机会；后台整理可让步。页面导航/点击/播放器操作按同一标签页串行，播放本身不长期占着点击锁，QQ SDK收发不占浏览器锁。数据库仍只有一个短事务提交入口。

事件驱动为主：新消息、片段变化、视频结束、任务到期、资源空闲才重新评估；低频时钟只补漏。不每秒调用LLM思考“我现在该干嘛”。没有合适的事时允许休息，不为制造活跃感编造活动。

聊天优先，但不把每条消息解释成“终止其他人生”。调度按显式用户指令、消息紧急性、活动可中断点和资源压力决定：

| 情况 | 行为 |
| --- | --- |
| 短问候/轻量交流 | 视频可继续，低频感知和聊天并行；感知跟不上时暂停或标记未处理区间 |
| 长对话/需认真回答 | 视频在安全点暂停，保存进度与理解水位，先交流 |
| 用户要求“继续看，跟我说说” | 保持活动，分享最新已验证观察；合并更新，避免每帧刷消息 |
| 用户要求停止活动 | 取消后续步骤，释放资源；取消不把已执行副作用变成未执行 |
| 私聊打断公开发帖准备 | 可以暂停草稿；已到外部发送边界的请求先核对结果，不能重复发表 |

“聊完”不是固定事实：显式结束可进入恢复评估；无新消息的短暂空闲只触发低优先恢复，不销毁聊天状态。用户再次发消息时再次让步，避免在观看/聊天间频繁来回切换。

## 4 活动状态与恢复契约

```text
proposed → queued → running
running → pausing → paused → resuming → running
running/paused → blocked | completed | cancelled | failed
blocked → queued（阻塞条件解除并重新核验）
pausing/resuming → blocked（环境或确认失败）
```

blocked要记录缺少的环境条件；重试只针对可重试步骤，不能把发帖或换头像一律自动重放。活动暂停不同于取消，取消不同于完成。

解除blocked需重新核验权限、资源和检查点，创建新步骤版本后才排队；不能直接沿用旧租约继续。暂停失败保留最后实际观测的播放状态并显示未确认，恢复失败保持不执行后续动作。completed/cancelled/failed不隐式复活，重新尝试需新活动或显式重试命令。

持久字段至少包括：activity_id、life_id、goal、reason/evidence、scene、priority、state、resource_leases、step_id/version、resume_policy、checkpoint、observation_watermark、pending_action_ids、next_check_at、budget和recovery_epoch。

视频检查点包含平台、账号、稳定video_id/URL、分P/合集/推荐流定位、播放器实际时间、播放/暂停状态、已处理的字幕/音频/画面区间、最近观察时间、兴趣理由和下一步。浏览器tab_id是临时句柄，不能当可持久的视频身份。

### 暂停与继续

1. 调度器写入pause_requested并阻止派发新步骤。
2. 可取消的模型任务发协作式取消；停止不了的调用结果带旧step版本，返回后不允许覆盖当前状态或直接发送。
3. 浏览器步骤尝试暂停，读回播放器与页面身份；提交经过确认的checkpoint。失败时标记pause_unconfirmed/blocked，不宣称视频已经停住。
4. 聊天在自己的任务中处理，无需等待慢字幕/页面操作完成才接收消息。
5. 续做时核对账号、页面/video_id、权限、epoch与资源；重新定位并读回时间。视频失效/无法定位时说明情况，不靠经过的墙钟时间假装恢复。

重启恢复只恢复持久任务和实际可核验位置；不声称关机期间继续看。沿用DSH在线时活动、关闭则停止的部署边界。若后续要求关掉DSH仍生活，需要明确改为常驻宿主部署，不能偷偷启动无人管理的后台生命服务。

## 5 观察、理解、分享与记忆

Observation保存来源、内容片段/摘要、视频身份、片段时间、采集方式、覆盖区间与置信限制。将“页面显示”“字幕陈述”“音频识别”“画面模型推测”“她的评价”分开记录。

播放器从2分播到5分，不代表系统理解了2–5分；必须另有感知覆盖水位。获取完整字幕后若阅读了未播放部分，应描述为“读到字幕后半段”，不能说“刚看到了那个画面”。只获得标题/简介时仅允许陈述这些来源支持的内容。

浏览器使用大肥鱼独立配置目录和获准站点，不能默认读取用户其他标签页/个人历史。音频只从获准视频页面采集；不得为省事持续监听整个麦克风/桌面。Chrome tabCapture之类能力有用户启动和权限条件，采集适配器要真实验证，不能假定永久无提示录制；权限不满足时使用可用字幕/画面并标明缺口。

分享当前活动经只读LiveActivitySnapshot：内容ID、链接、位置、已理解片段、更新时间、可披露短评。快照过期或当前内容已切换时先刷新，不能把旧视频说成此刻正在看。不把整个浏览器历史或其他人的私聊送进聊天模型。用户询问/同意陪看时可持续分享，状态变化合并推送；后台自发分享是独立能力，有授权范围和频率控制。

一般保存片段来源、少量必要观察和她的理解，不默认复制整个视频。感兴趣或对关系有意义的见闻形成长期记忆；机械逐帧事件不全部提升为重要经历。以后可以回忆“之前看过某片段并和你聊过什么”，仍需分别关联观看证据与交流证据。

## 6 自主社交与权限体验

采用能力授权，而不是每做一件小事都向用户请示。用户启用并设置范围后，她能自行判断和执行：

| 能力 | 授权范围示例 | 执行/结果要求 |
| --- | --- | --- |
| 主动私聊 | 允许联系的人、时段、频率 | 有活动/关系/承诺等理由，过期不集中补发 |
| 分享视频 | 允许的对象、站点、更新频率 | 实际内容来源、视频链接和自己短评，不泄露其他场景 |
| 改头像 | 大肥鱼账号、素材来源、更新频率 | 图片预处理、固定asset hash、发送后读回；超时未知不随机再换 |
| 发说说 | 大肥鱼空间、可见范围、允许的内容类别、频率 | 草稿与源材料权限检查、持久action_id、发表返回tid、可见范围核对 |
| 浏览视频 | 允许站点、登录账号、时间与计算预算 | 页面与感知证据、可暂停续做；点赞/关注/评论属于另外的写能力 |

启用能力不是本次对话已经授权登录、发布或更改账号。实现和联调时绑定具体专属账号，避免把用户本人账号当大肥鱼身份。授权后常规动作不逐次确认；购买、付费、对外共享私密内容等不从“自主生活”推导出许可。

说说可见范围必须随动作显式保存并传入，不能继承网关默认公开；首次配置未授予可见范围时不发表。联调使用自己的账号并设自己可见；正式自主发表遵循用户给定范围。头像选材同样绑定获准素材来源，不能任意拿其他人的私密照片作头像。

前稿“主动外发默认关闭”只保留为未完成账号/范围配置时的安装初态，不能作为长期关闭自主能力的交付。前稿每对象每日2次是聊天版建议，不作为本目标固定上限；新配置分别管理新话题发起、当前对话回复、用户请求的陪看更新，不能用同一限额截断正常交流。具体频率是可调整产品参数，不是人格本体。

## 7 模块责任与开发优先级变化

| 模块 | 必须新增/增强 |
| --- | --- |
| M02 | 多活动协调、优先级、资源租约、取消代次、提交顺序与恢复 |
| M03 | 浏览/播放/感知/发布的真实观察和结果事件 |
| M04/M06/M07 | 观看与交流可连接的经历、兴趣与习惯演化；不把自生成内容算独立证据 |
| M05 | 情绪/心境影响活动选择和表达，不修改权限 |
| M08 | 生活目标、兴趣驱动、活动状态机、检查点、恢复/放弃判断；成为主要产品能力 |
| M09 | 聊天和视频各自有界上下文、多模态感知、实时活动快照 |
| M10 | 普通QQ/空间能力、B站/抖音站点驱动、播放器与感知适配器 |
| M11/M12 | 发帖/头像/消息/浏览步骤分型、不可逆边界、授权和实际回执 |
| M13 | activities、activity_steps、checkpoints、observations、resource_leases与原事务体系整合 |
| M14 | 托管内核与受控浏览器启停、模型请求优先级、工作进程取消 |
| M15 | 当前在做什么、为什么、看到哪里、并行状态、暂停/继续、活动历史与能力授权 |

自研重点从“聊天上下文+记忆注入”转为“活动与注意力协调+真实观察+持续状态”。SeekMemory继续复用适合的记忆/人格部分，不把其已有Runtime宣称为完整自主生活运行时。

第一个可演示验收闭环改为：**普通QQ收发 + 实际B站观看 + QQ消息打断 + 有依据地交流当前片段 + 恢复同一视频**。第二条验证边看边聊；第三条验证主动私信/改头像/发说说；随后完成抖音站点、长期兴趣/承诺与完整管理。数据/隐私/Outbox基础从第一个闭环就具备，不能等到自主行为全部开发后补。

## 8 必须通过的新增验收

1. 同一个视频播放/感知期间收到QQ，入站和聊天调度不被页面操作阻塞；分别记录入站持久延迟、注意力切换延迟和完整模型回复耗时，不承诺模型瞬时回复。
2. 轻量聊天期间观看继续；感知积压时正确降频/暂停；不能编造未处理片段。
3. 深度聊天触发暂停并读回；聊完恢复相同视频/分P和检查点允许误差内的位置；新消息再次打断不丢状态。
4. 正在切换视频、收集字幕、生成回复、暂停确认时分别崩溃；重启不重复发布、不伪造进度、不使用旧tab句柄冒充原视频。
5. 发说说/换头像请求已提交平台后聊天打断或超时，进入回执核对；不回滚成“从未发送”再发一次。核验tid/头像读回与目标账号。
6. 正在观看公共视频但来源记忆含私聊，主动说说不泄露私聊；分享活动快照也不能泄露其他浏览活动。
7. 登录过期、页面改版、视频删除、字幕缺失、音频授权失效均显示真实受限状态；无输入时允许休息，不能假造已看/已发经历。
8. 长时间没有消息能在授权与预算内自行选事；没有模型额度时停止新增推理活动并保留任务。任务优先级有饥饿检测，聊天结束后后台任务可以继续。

## 9 当前核实的能力与来源

- NapCat固定源码 `98d781d19815d1625b24d717ce280ecf0a4f6d0c` 有公开动作 `set_qq_avatar` 和 `send_qzone_msg`，后者支持纯文/多图及可见范围参数，返回tid等；这些是源码能力，尚非本机账号验收。[头像动作](https://github.com/NapNeko/NapCatQQ/blob/98d781d19815d1625b24d717ce280ecf0a4f6d0c/packages/napcat-onebot/action/extends/SetQQAvatar.ts)、[说说动作](https://github.com/NapNeko/NapCatQQ/blob/98d781d19815d1625b24d717ce280ecf0a4f6d0c/packages/napcat-onebot/action/extends/SendQzoneMsg.ts)。
