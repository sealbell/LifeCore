## 2 先保留什么，不替用户重新选择

以下依据仓库中的历史确认记录继续作为设计输入：

- DSH 为宿主，单个正式生命；普通 QQ 经 SnowLuma 接入的预览选择已经记录，不重新退回官方 Bot 或 NapCat 默认路线。[来源：完整设计开头补充、v0.1 计划]
- 自然语言设定、草案和试聊并排、选择初始记忆、独立确认可选关系、正式出生；未选择试聊不进入正式生活；两个预设是草案起点。[来源：M01 第 1–7 节]
- 共同经历和重要事情可自动保留；用户能查看、纠正、删除；主动联想具有独立开关，其新部署默认值未确认。[来源：M04、M09、讨论登记]
- 完整目标包含自主活动、B站/抖音、聊天打断和续做、授权社交及工作；不能因现有插件缺某项功能就默默删除目标。[来源：自主生活修订、完整设计第 1 节]
- DSH 关闭后停止活动，重启恢复已有生命，不编造离线经历；已确认版本、原始来源、执行结果和场景隔离仍需保留。[来源：完整设计及 M01]

本轮尚未决定：采用 LivingMemory 还是 SeekMemory、是否长期保留 Python 内核、是否固定四层物理存储、每个场景的 DSH Agent/session 对应方式、压缩责任、具体预算数值、每项能力进入哪个发布阶段。

## 5 三条架构路线及建议

| 路线 | 适用条件 | 主要代价 | 当前建议 |
| --- | --- | --- | --- |
| A：主要自研，复用库级代码 | 现成插件无法满足核心契约 | 要维护检索、工具调用和平台变化，开发范围最大 | 作为具体能力不满足要求时的局部后备，不全面默认采用 |
| B：组合完整生活/聊天/记忆插件 | 插件间已有兼容的身份、调度、状态接口 | 接通很快但容易出现多套记忆、多个回复者、暂停不同步 | 未有契约证据前，不直接用于同一正式生命 |
| C：LifeCore 管生命规则，DSH 管执行，插件提供能力 | 通过接口适配满足身份、权限、回执和恢复要求 | 需要薄适配层及少量缺口实现 | 推荐方向；用户已要求开始梳理，但尚未逐项确认此方案及组件选择 |

### 5.1 推荐分工的具体含义

**LifeCore**：定义唯一身份、关系/人格变化、经历含义、活动优先级、场景权限、来源和完成标准。规则的部分实现也可复用，不要求所有领域算法从零写。

**DSH**：优先复用 Agent 的执行循环、工具注册与调用、模型路由、会话运行、宿主生命周期、设置入口。精确接口与作用域按选定版本核查，不照抄最新 master 接口到旧宿主。

**能力插件**：提供搜索、内容提取、播放器操作、平台传输、记忆提炼/检索等明确能力。插件自己的数据库、登录态和缓存不自动变成生命状态的第二份权威。

**适配层**：连接现成接口，映射来源、范围、错误与回执；优先使用公开工具或服务，不读取插件内部表假装稳定 API。缺口清单必须解释“为何配置无法解决”，才考虑补丁或自研。

一个生命可以有多个按场景/任务隔离的执行 Agent，不等于所有私聊、群聊、工作都挤在一个会话。M02 决定业务顺序与状态提交，M08 决定生活活动与注意力，DSH 负责具体 Agent 执行；三者不能各自独立重试同一外部动作。

### 5.2 记忆后端暂不锁定

两种可评估方式：①插件提供提炼/检索，LifeCore 持有原始经历及正式状态，插件保存可重建派生物；②插件通过满足契约的稳定接口成为某类记忆的唯一权威，LifeCore 保留身份、来源引用和活动等其他状态。方式②可能更省开发，但必须证明导出、版本、纠正、删除、隔离及恢复能力。

不要求现在同时实现两种方式。LivingMemory、SeekMemory 都按同一组要求评估；达不到要求时记录差距，不直接再造一整套竞争记忆系统，也不把所有要求悄悄降成插件已有功能。

## 6 十五模块责任盘点与下一份设计要回答的问题

“生命权威”指谁决定该状态的正式含义，不代表固定数据库、编程语言或进程。下列均为细化方向，未冻结接口。

| 模块 | 必须有明确权威的内容 | 优先复用与需要保留的工作 | 下一份设计必须给出的结果 |
| --- | --- | --- | --- |
| M01 身份与出生 | life_id、确认档案、初始导入及修订来源 | 保留预览的身份/版本思路；DSH 提供试聊执行 | 出生/修改/导入流程；试聊与正式隔离；导入原子性和重复确认结果 |
| M02 协调器 | 命令、版本、取消代次、提交/恢复次序 | DSH 执行 Agent；LifeCore 保留业务协调 | 消息到任务的持久交接、并发与取消规则、跨插件结果接收协议 |
| M03 事件与经历 | 主体、场景、来源、真实发生、修正及去重 | 可引用 DSH/插件日志；不能仅依赖会被清理的临时路径 | 规范事件类型、可保留证据的载体、来源丢失语义、统一事件 ID 映射 |
| M04 记忆 | 记忆含义、来源、时效、版本与可见范围 | 优先评估记忆插件；只补实际缺口 | 后端比较、原文与派生物归属、检索/写入/纠正/删除/导出契约 |
| M05 情绪与心境 | 情绪变化原因、持续时间与表达影响 | 评估可用规则/算法；不因记忆插件有评分就直接等同情绪 | 状态维度、更新时间、离线时间含义、反例及可回放变化规则 |
| M06 关系 | 可信账号绑定、关系对象、关系依据 | 平台插件提供可靠账号 ID；关系仍独立于授权 | 同名/换号/跨平台流程、关系维度、边界和纠正办法 |
| M07 人格演进 | 出生档案与当前人格修订分离 | 可复用候选提炼，正式变更由统一规则判断 | 可变/不可自动变范围、证据门槛、反证、历史修订和撤销规则 |
| M08 自主活动 | 目标、承诺、优先级、检查点、恢复意图 | 复用任务执行/时钟；接管或关闭完整插件独立作息 | 活动状态机、并行资源、轻聊/专注判定、预算、打断和重启恢复 |
| M09 认知与上下文 | 本轮可用材料、理解覆盖、回忆表达 | 优先复用 DSH 提示词与工具循环；记忆插件供候选 | 输入装配顺序、压缩责任、工作段、主动联想开关、最终请求可核对 |
| M10 平台与能力适配 | 原始账号/媒体/平台标识到领域语义的映射 | SnowLuma 和视频工具插件优先；补能力探测与映射 | 各平台读/写/播放/理解矩阵、登录及失效、账号隔离、替换边界 |
| M11 行动与回执 | 动作意图、执行尝试、真实结果、未知状态 | 插件执行发送/修改/播放等操作 | 执行前授权检查、幂等与结果核对、失败/未知/取消后的处理 |
| M12 权限与隐私 | 可信主体、场景、能力许可、撤销版本 | DSH 作用域和工具限制作为执行手段，不能代替业务规则 | 检索前授权、注入和后台权限、读写范围、撤销传播与信任边界 |
| M13 存储与恢复 | 各类数据权威位置、恢复代次和删除状态 | 复用 SQLite/插件存储与备份接口；不强求一库 | 数据目录清单、跨库一致性、迁移、恢复顺序、删除恢复防复活 |
| M14 DSH 集成 | 插件/Agent 生命周期及能力接入状态 | 优先公开 Agent、tools、systemPrompt、设置 API | 固定宿主接口、可选依赖、能力装卸、版本变化、暂停及停机协议 |
| M15 管理与可观测性 | 管理操作意图与用户可见状态 | 复用 DSH 设置和插件原有配置页，避免重复配置 | 出生/活动/记忆/权限/费用页面职责、权威来源标识、错误和待核对状态 |

每份模块规格采用统一结构：目标与反例 → 已确认/待决 → 输入输出 → 数据归属 → 正常流程与状态机 → 并发/取消/失败/恢复 → 复用组件与缺口 → 相邻模块契约 → 验收场景。接口签名和数据库表在公共语义定稳后细化，不先以现有实现倒推产品规则。

## 7 先走通的完整场景与责任交接

### S01 出生并建立连续身份（映射 E01/E02）

M15 展示 M01 草案 → M14 提供隔离试聊 → M03/M04 保存试聊来源 → 用户选定初始记忆、可选关系 → M01/M06 核对 → M02/M13 提交确认版本。失败不得显示出生成功；记忆插件不能把未选试聊自动写入正式空间。需明确已确认初始内容在插件不可用时是整体拒绝出生还是进入可恢复准备态，不能部分成功。

### S02 看视频时收到 QQ 消息（映射 E06/E09/E12/E14）

M08 选活动 → M12 许可 → M10/M14 调用发现/读取/播放能力 → M03 记录实际获得的材料，M08 保存播放位置，M09 保存理解覆盖。收到 QQ 后，M10 识别主体与场景，M02 持久接收并安排处理；M08 决定并行或暂停，M11 核对暂停结果；M09 只取获准的新鲜快照和证据，DSH 执行回答；M11 保存 QQ 实际回执；M08 再评估是否继续原活动。

仍需细化：不能暂停的插件如何处理；聊天内容是否足以要求专注；播放器时间与理解区间分别如何恢复。内容工具只返回摘要时，记录为“读取了摘要”，不伪装为完整播放和理解。

### S03 通过 QQ 交办工作（映射 E06/E07/E12）

M06 提供可信人物绑定 → M12 检查此人的任务能力与输出接收者 → M08 创建持久任务 → M14 在任务作用域提供允许工具 → M11 核对产物与交付结果 → M03/M04 保存必要经历。普通社交会话不能因宿主装有 Shell 插件就获得系统操作权；任务文件不自动进入全局人格记忆。

### S04 记忆纠正与自然回忆（映射 E03/E04/E07）

M03 记录明确纠正 → M02 使旧“当前事实”失效 → M04 更新或屏蔽派生物 → M09 在下一次回答中使用新状态。后台提炼滞后不允许旧值冒充当前。主动联想关闭时仍可保存记忆和回答明确回忆问题，不能关闭全部记忆，也不能在重新开启时补发旧联想。

### S05 情绪、关系与人格变化（映射 E05/E14）

独立新经历 → M03 保留依据与反证 → M05/M06 各自提出短期状态或关系变化 → M07 按更长时间与证据条件评估人格候选 → M02 提交版本 → M09 使用当前状态。重复消息、模型自述、检索命中次数不能变成多份独立成长证据；情绪不能修改权限。

### S06 暂停、掉线和重启（映射 E08/E09/E13）

M15 请求暂停 → M02 标记新代次 → M08 停止新活动 → M14 停止受管 Agent/定时器 → M11 将已开始但无法确认的动作保留为待核对。恢复需重查权限、账号、插件版本和资源；不重放历史发送。第三方钩子/自主定时器也要遵守暂停协议，不能仅停止 LifeCore 聊天接口。

### S07 删除与旧备份恢复（映射 E10/E13）

M12/M13 登记删除范围与版本 → M04/M09 清理或隔离摘要、图、向量、缓存和宿主上下文 → M14 协调相关插件 → M15 显示已完成与待处理位置。恢复旧备份先对齐最新删除状态再开放查询；插件无法删除/导出时必须有明确产品限制或替换方案，不能宣称全链路删除完成。

### S08 插件安装、升级、更换与卸载（新增验收候选）

安装成功 → M14 发现能力及版本 → 用户/管理员配置账号和能力范围 → 契约验证 → 对指定 Agent 启用。升级先核对接口和数据格式；卸载时撤销能力、处理在途动作、标记活动受阻，生命身份和权威经历仍可恢复。记忆后端替换应验证导出、来源映射和查询一致性，不能运行时静默切到空库。

## 9 插件接入的设计准入条件

这些是之后验证的要求，本轮不安装或启动插件：

1. **入口可用**：明确工具、服务、事件钩子还是独立 Agent；仅 UI 播放组件不能自动算模型能力。
2. **范围可控**：实际工具执行、自动注入、后台任务和插件自有 API 均受接入策略约束；外围 wrapper 不会自动约束插件内部行为。不能控制时选择配置关闭、作用域隔离、最小补丁或不接入该能力。
3. **状态可对齐**：身份和账号可靠；活动、来源与真实结果可映射；不能以自然语言“完成了”代替回执。
4. **数据可管理**：权威数据、缓存、登录态和日志位置明确；保留/删除/导出/恢复覆盖插件自身存储和宿主记录。
5. **成本可解释**：本地数据库不等于无外部模型调用；插件独立提炼、重排和向量费用需纳入预算，不能只统计 DSH 主回复。
6. **替换成本有界**：固定目标版本及来源、记录最小适配差异；升级接口变化可检测，卸载不会重新出生。

验证证据分别记录：文档声明、指定源码确认、临时数据运行、真实宿主兼容、真实账号能力、整条场景验收；不把这些证据排列成一个可自动推导的“通过”等级。

### 10.2 防止后续设计再次漂移

- 产品需求沿用 V1-Mxx 编号；新增目标新增编号，不删除原编号。每份规格列出其覆盖需求、决定记录与验收场景。
- 决策记录保存日期、决定者、方案、理由、证据和受影响模块。用户确认、工程推荐、代码事实分别记录。
- 决定变化先更新权威入口和依赖清单，再修改相邻模块。不能只改某个模块后让其他文档继续依赖旧接口。
- 模块详细规格未定案，或仍有影响权威数据/身份/权限的未解冲突时，不标记“可开发”。
- 每个开发任务最终对应：需求 → 规格 → 契约 → 任务 → 验收证据。自动测试不能代替真实平台能力核对。
