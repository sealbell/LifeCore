# LifeCore 设计梳理 05：记忆适配接口、数据字段与一致性流程

日期：2026-11-02（Asia/Shanghai）。状态：接口语义建议稿；不开发、不安装、不运行实验。

承接：[03 共同契约](2026-11-02-common-contracts.md)、[04 复用评估](2026-11-02-memory-context-reuse-design.md)。本稿沿用“LifeCore 领域记忆权威＋一个受控派生后端”作为讨论前提，用户要求继续细化不等于批准该权威方案。具体候选改动与新源码证据见[适配改动对照](2026-11-02-memory-adapter-change-map.md)。

本稿明确讨论所需的语义，不冻结语言、HTTP/进程内传输、数据库或序列化实现。文中操作名称不是任何上游已有 API。M03 拥有来源，M04 拥有记忆规则，M12 拥有权限，M02/M13 组织持久提交，M09/M14 管材料和执行；适配器负责忠实映射、受控调用与可核验回执。

## 1 这层适配器负责什么

推荐“领域命令与查询＋幂等投影”，而不是通用 CRUD 透传。普通模型只提出记忆候选和查询线索，不能填写可信身份、覆盖版本、删除水位或恢复资格。领域状态已经提交后，后端才能应用派生表示。

| 路线 | 取舍 |
| --- | --- |
| 直接透传插件 remember/forget/search | 接线少，但各插件版本、去重、遗忘和 scope 含义不同，不能直接形成共同契约。 |
| 领域协议＋受控适配 | 本稿推荐：固定业务语义，复用后端机制；后端只保管授权范围内的数据，查询结果回到权威状态复核。 |
| 后端原生充当记忆权威 | 仍可另案比较，但必须证明相同提交/删除/恢复保证；本稿不同时维护这条路线。 |

适配器不再建立自己的独立人格、关系或外发状态。技术缓存、向量、图邻居和检索统计可以存在，但不能独立改变业务事实、共享权限或已发生动作。

## 2 基础标识、版本与水位

所有 ID 是不透明字符串；平台大整数以无损字符串传递。时间为带时区的明确时间点，另记精度/未知，不以接收时间伪造发生时间。版本是所属对象内部的有序修订，不能比较两个不同对象的版本大小。

| 字段组 | 必需语义 | 规则 |
| --- | --- | --- |
| 协议 | contract_major/minor、schema_revision、canonicalization_revision | 不支持的主版本拒绝；权限/删除/来源含义不明的字段不能静默忽略。新增可选展示字段才可声明兼容。 |
| 数据域 | realm_kind=formal/trial、realm_id、lineage_id | formal 关联 life_id，trial 关联 trial_id；二者不能靠 ID 缺省混用。所有实体/操作在数据域内解析。 |
| 来源身份 | source_namespace、source_key、source_id | source_namespace 含平台/账号及原 ID 有效范围；source_id 独立于正文哈希，重连/恢复不重置来源身份。 |
| 来源修订 | source_revision、provider_revision、predecessor_ref | 内部修订由 M03 分配；provider_revision 保留为不透明证据，不假定平台值可排序。 |
| 领域修订 | memory_id、memory_revision、expected_revision、commit_seq | M04/M02 分配与 CAS；commit_seq 为本控制流顺序，不是记忆内容版本或外部平台时间。 |
| 执行隔离 | binding_generation、incarnation、restore_generation | 用于执行资格；不参与来源去重身份，不授予历史动作再次执行资格。 |
| 派生位置 | backend_id、backend_generation、namespace、mapping_revision | 区分供应者、索引代次与映射规则；本地条目 ID 不能脱离这些字段单独解释。 |
| 约束水位 | policy_revision、control_seq、reconciliation_watermark | 分别表示授权规则、删除/撤销屏障和当前事实协调状态；禁止相互替代。 |
| 覆盖 | stream_id、contiguous_applied_seq、covered_ranges、gap_ranges | 每条相关流记录连续前缀和缺口；最大见过的 seq 不表示之前都已完成。 |

后端 ID 映射键至少包含数据域、实体类别、实体 ID、实体版本和后端代次。若一个版本拆成多个块，必须有稳定 chunk_id 与完整成员清单。版本与平台字符串分别存，不能让模型分配自增版本。

## 3 数据对象与字段

### 3.1 SourceRecord / SourceRevision：发生过什么、证据是哪一版

| 字段 | 含义与校验 |
| --- | --- |
| source_id、source_revision、source_key/provider_revision | 唯一来源及修订关联；同源键/修订不同载荷必须 conflict，合法编辑新建修订。 |
| realm、scene_id、principal_ref、participants | 可信入口产生；关于谁、谁说的、谁允许访问分别记录。昵称、正文自称、插件 cwd 不作为身份依据。 |
| source_kind、evidence_class | 用户陈述、工具观察、管理确认、模型候选、动作回执、历史导入分别标记；助手生成文本不是成功发送证据。 |
| occurred_at/range、time_precision、received_at、commit_seq | 发生与记录时间分开；乱序编辑若不能确认先后，保持 pending/conflict，不用最后收到覆盖当前头。 |
| payload_ref、payload_digest、media_type、representation_revision | 引用已经耐久且获准留存的版本；引用不可直接变成任意本地文件路径或网络抓取授权。 |
| availability | present / partial / missing / erased；缺附件、仅转写、来源不可得均明确。留存获准的内容才能保存，未获准的正文不能进入诊断。 |
| predecessor_ref、change_kind | edit/correction/retraction/attachment_added 等；平台撤回是事实变化，不自动等于本地全面删除请求。 |
| retention_ref、access_policy_refs、control_seq_seen | 引用当前规则；保存时允许不代表以后仍可读/可出站。 |
| related_action/attempt/receipt_ref | 对结果来源关联可信回执；不使用“我已经做了”这类文本更新动作成功。 |

修订正文通常不可就地覆盖；删除、保留到期是明确例外，允许移除字节并留下最小状态壳。平台编辑生成新修订；附件晚到或 ASR/OCR 重跑创建新的表示版本，不能让旧偏移指向新内容。

### 3.2 EvidenceRef：精确引用

每条断言引用 source_id＋source_revision＋representation_revision＋selector＋digest。selector 必须声明类型：

- 文本：基于指定不可变文本表示的 Unicode code point 半开区间 [start,end)，不是 UTF-16 下标；归一化规则独立带版本，不先改正文再沿用旧偏移。
- 结构化结果：固定 payload 版本中的字段路径和可选数组项标识；数组变化后旧引用不得重新解释。
- 音视频/图像：固定资源/转写版本、轨道或帧引用、毫秒区间及精度；有转写不等于看过画面。

selector、摘要、标题、hash 都继承访问限制。无原文时返回 missing/erased/partial，不能从摘要重造“原话”。正文摘要只作完整性核对，不是来源身份、授权或语义正确性证明；敏感摘要不公开，必要抑制记录使用受保护承诺，不保留被删正文。

### 3.3 MemoryCandidate 与 MemoryVersion

| 字段 | 含义 |
| --- | --- |
| proposal_id、job_id、purpose、processor_revision | 候选属于哪个持久任务、提炼/纠正/整理目的与规则版本；同任务重试不变成新经历。 |
| memory_id、expected_revision、memory_revision | 新条目声明预期不存在；修订明确当前头。只有提交成功才产生正式 memory_revision。 |
| kind、subject_refs、episode_ref、claim_ids | 事实、经历表达、解释/反思、工作摘要分别建模；断言有稳定逻辑标识。不是每段文字自动新建人物或情节。 |
| assertions/structured_value、expression | 断言与可读表达分开；每个实质断言关联 EvidenceRef。解释标为解释，不能升级成观察。 |
| valid_from/to、recorded_at、time_precision | 有效时间与入库时间分开；过去正确、现在被替代不等于应删除历史。 |
| epistemic_status、lifecycle_status | 已支持/有争议/不足证据，与 active/superseded/blocked/erased 等生命周期分别表示。 |
| evidence_refs、derived_from、dependency_manifest | 包含源修订、上游记忆版本、作用域约束和处理规则；记录可反向追踪依赖。图关系也有来源与版本。 |
| importance、confidence、retrieval_score、usage | 重要、可信、相关和使用次数分开；检索/注入/摘要重算不构成独立经历。 |
| access_policy_refs、retention_ref、suppression_refs | 继承来源限制及人工覆盖；候选不能自行扩大范围、取消保留约束或解禁。 |
| disposition/result_ref | committed/rejected/stale/conflict/blocked、正式结果引用及后续投影状态；模型不能把 proposed 写成已记住。 |

模型可提候选来源 ID，但程序必须核对真实存在、版本、选择范围与逐断言依据。没有新事实的成功提炼保存 empty_result＋覆盖区间，区别于调用失败；不得以失败推进提炼完成水位。

### 3.4 AccessContext：谁能为什么目的使用哪些材料

可信访问上下文至少包含 principal_id、realm、scene_id、purpose、允许操作、资源范围句柄、目标端点/受众、grant 引用、policy_revision、control_seq、运行代次、过期时间与预算引用。由认证入口/M12 产生，不能从插件参数、导入包、模型或记忆里反序列化成可信授权。

权限范围表达为可验证的规则/资源允许集合，不能仅有“private/global”字符串。多来源派生物必须同时满足所有来源约束；同一来源允许多个受众可以是规则内部的“或”，多个来源之间是“且”。不能把标签字符串做集合交集后误判为空，也不能用最宽来源扩大权限。不能合法共用的材料分开表达；任何脱敏/公开摘要都须单独审核生成当前允许的派生版本。

权限检查必须覆盖候选枚举、图扩展、原文回退、排序服务出站、最终返回、模型请求和对外表达。读权限、模型端点许可、分享许可、导出许可分别判定。策略服务/最新屏障不明时返回 unavailable，不回退 global。

### 3.5 ProjectionRecord / CoverageManifest

投影包含 memory/source 版本、固定内容摘要、backend_generation、mapping_revision、chunk_manifest、来源依赖、访问约束、control_seq_seen、operation_id 和应用证据。投影可以一对多，不可丢 provenance 后只留字符串。

索引 manifest 记录模型/分词器/维度/算法版本、连续覆盖与缺口、依赖的权威快照、控制水位和 ready 状态。新的向量模型创建新 generation；不同模型向量不混排为同一种可比较分数。某分区覆盖完成不代表全生命覆盖完成。

## 4 操作接口与返回语义

所有变更请求有公共信封：contract_version、request_id、operation_kind、realm、可信调用上下文、业务 payload 摘要、expected_versions、trace_id。一次模型调用/写尝试另有 attempt_id。许可凭据不进业务摘要或导出；具体目标和数据范围必须进摘要，防止同键换接收对象。规范化版本固定，不能无差别折叠否定词、空白或来源顺序。

| 操作组 | 关键输入 | 可查询结果 / 成功点 |
| --- | --- | --- |
| PrepareImport / QueryImport / CancelImport | 出生操作/迁移计划、确认快照、源映射、准备 namespace、request_id | prepared manifest 或 blocked/cancelled；不等于出生成功。正式激活以 03 的 B5 为准。 |
| ProposeMemory / CommitMemory / QueryOperation | 受管任务、来源与断言、预期版本、候选 | committed 返回版本与 commit_seq＋projection_pending；领域内容/幂等结果/outbox 同一提交才可称已保存。 |
| ApplyProjection / QueryProjection | 已提交版本、operation_id、backend_generation、控制水位、块清单 | applied 返回后端同一效果的证据/水位；pending/unknown 不伪称失败或完成。 |
| Recall / ReadEvidence | 查询目的、可信访问句柄、时点、相关对象、必需协调/覆盖水位、预算、游标 | candidates/证据及版本、coverage、degraded/missing；结果最终使用前再校验。 |
| DeleteMemory / RevokeAccess / QueryDeletion | 经认证目标、范围、预期版本、抑制策略、request_id | accepted、blocked_from_use、copies_pending、erased_in_managed_scope 等分阶段结果。 |
| ExportMemory / QueryExport / ReleaseExport | 类型、筛选、目标、授权、snapshot 要求与格式 | preparing/ready/released；只有完整校验和发布资格通过才可交付，备份可恢复性另判。 |
| ValidateImport / StageRestore / ActivateBackend | manifest、来源谱系、目标后端、最新控制证明、预期 active generation | validated/staged/active；验证不自动授权读取，不自动执行历史任务。 |
| PauseAdapter / QueryHealth / Reconcile | 数据域/后端代次、暂停目的、待核对操作 | 明确哪些入口已停、在途尝试与缺口，不用单个 healthy=true 覆盖部分故障。 |

错误沿用 03：conflict/stale/denied/unavailable/blocked/outcome_unknown。unknown 原因说明是“后端写入结果待核对”还是“外部动作结果未知”；两者都不能用盲目重试解决，但各自查询不同账本。权限不足的查询不泄漏对象存在性。授权改变后，同 request_id 也必须重新验证调用方可查询的结果范围。

## 5 来源到记忆、再到投影的完整写入流程

### 5.1 来源修订与当前事实屏障

1. M03 依可信 source_key/provider_revision 核对重送和合法编辑，M02 原子写获准来源、修订关系、处理待办及协调脏水位；接收后才确认。
2. 新纠正可能改变当前事实时，先阻止受影响旧“当前事实”进入上下文。能精确定位则限于相关断言；无法确定时按该授权场景的派生当前事实保守标 pending，不污染无关人格/可信账号绑定。
3. 受管提炼读取明确 source revisions 与当前记忆版本，形成候选。期间编辑/删除/撤权使受影响候选 stale，不允许它改读新原文继续沿用旧依据。
4. M04 校验、M02 CAS 提交新的事实头/历史关系、依赖边、候选结果、提炼覆盖和投影 outbox。争议不是选择“最后写入者”；明确记录尚待核对。
5. 当前事实读需越过必需协调屏障；权威原文仍可按权限读取。索引未追上时补查原始尾部/权威查询并标降级，不能把旧事实当当前或把索引缺口说成从未发生。

### 5.2 幂等键与重试

幂等空间为数据域＋操作种类＋可信请求主体域＋request_id；同键同规范化业务载荷返回同一逻辑结果，同键异载荷 conflict。冲突键与业务唯一键分别存在：换 request_id 不能绕过同 job/候选的唯一提交，也不能重复出生。

第一次请求在事务内占位并绑定摘要；领域变更、版本、operation result、outbox 一起提交。断线后先查结果。若提交完成但后端没更新，继续原投影任务，不重新提炼/再次建立 memory。过期候选重算需显式关联原任务和新版依赖；改变业务载荷不能复用原幂等键。

每次尝试有独立 attempt_id、运行资格与状态；超时/租约到期不证明未写。重复 learn 引起的计数、强化、来源追加和审计记录也是效果，不能只检查最终正文相同。内容相同但不同来源是不同证据，语义合并须另经 M04，不能拿正文去重代替事件去重。

删除后保留最小请求/来源/抑制壳，不保留明文副本。查询返回当前可见状态而非历史响应正文；重试不得重建已删除内容。精确保留期限由重放/备份策略确定，未经新的隔离证明不能提前清掉必要防重证据。

### 5.3 后端投影与跨存储崩溃

1. 控制 outbox 持久保存 operation_id、目标 generation、版本与完整 chunk manifest。
2. 适配器先核对当前 generation、暂停、源版本和 control_seq，按稳定键准备所有块；准备态不可被普通搜索、图、维护或导出读取。
3. 后端应用需要“效果＋应用证据”同一提交，或能以确定性版本替换及完整内容/副作用核对证明等价。仅在另一张控制表先写 done、再调用插件不满足。
4. 全部必需块完成后发布该版本的 ready 标记，再确认 applied。控制层记录回执与连续覆盖；在后端已写、控制未确认处崩溃，查同 operation/generation 恢复，不重算业务事实。
5. 不支持原子多块的后端采用隐藏 generation/manifest 门控；任何一个读取/后台入口绕过门控则该方案不准入。批量多个独立记忆允许逐项结果，但单条记忆不能半个版本公开。
6. 乱序旧投影不能覆盖新版本或墓碑；按实体 revision 和 control_seq 双重防旧写。已有新状态返回 superseded/blocked，不把旧操作伪称 applied 后推进无证据覆盖。
7. 若无法证明旧调用结束或写入结果，隔离旧 namespace/generation，查询或从权威记录重建新派生代次；旧存储不再读/自动维护/导出。不能仅切换指针就声称旧数据已清除。

覆盖清单区分 applied、经核验的 superseded/tombstoned 与 unresolved。旧操作若已由可验证的新版本或墓碑完整涵盖，可记录替代证据后关闭该缺口；不能因它不再需要执行而永久卡住水位，也不能仅凭“应该过时”跳过。

后端不支持可靠操作回查且写入带不可核对增量副作用时，必须改写其提交入口或换路线。外围 request cache 无法解决“后端成功、cache 未落盘”的窗口。

## 6 查询与上下文一致性

Recall 返回受限候选，每项至少有 memory_id/revision、kind、表达/断言、EvidenceRef、有效时间/争议、依赖与范围引用、匹配理由和索引 generation。响应包含查询快照、协调/索引覆盖、缺口、健康状态及分页游标；不得只返回无来源文本。

- 查询开始前解析可信范围，搜索/图扩展只处理允许候选。拿到 ID 后到权威记录核对当前版本和删除/来源状态，再允许读取内容；向量库或外部 rerank 不能先接触越权材料。
- 分页游标绑定 realm、查询、访问范围、版本和快照；每页重查当前撤销。快照过期/变化导致不可安全续页时返回 cursor_stale，不扩大范围或把不同快照拼成完整结果。
- 历史查询可读授权且未删除的旧修订，但不能绕过当前删除/撤权；当前事实必须通过协调屏障。
- optional 检索服务故障可显式降级；必需当前事实、身份/权限/删除核验不可用时阻断依赖它的回答。不把 unavailable 返回为空数组掩盖。
- Query/ReadEvidence、上下文装配、实际模型出站依次核对相关依赖；缓存包含 realm、scene、purpose、源/事实版本、策略、索引/恢复代次。删除/撤销主动失效，不能只等 TTL。
- 上下文的注入/被使用/实际提及分别记录；使用统计可以异步，但按一次真实事件键去重，不能成为隐含记忆写入入口。

## 7 删除、撤权与恢复

### 7.1 先明确目标

| 管理意图 | 必须明确的范围 |
| --- | --- |
| 纠正事实 | 新来源/记忆修订与替代关系；旧版可保留为历史但不冒充当前。不是自动物理删除。 |
| 删除某条记忆表达 | 删除表达及依赖副本，并建立重新提炼抑制；来源是否保留必须显示。 |
| 删除来源/经历 | 目标源修订或整个源对象及选定范围；清理由它产生的断言、图、摘要、向量、缓存和可控副本。 |
| 撤销共享/出站许可 | 立即停止该用途和受众使用、失效相关副本；不自动等同全部保留副本物理清除。 |
| 删除某主体资料 | 先在认证管理范围解析主体及相关来源/派生闭包，预览范围；同名不能直接批量删除。 |

DeleteIntent 必须携带 deletion_id、realm/lineage、目标稳定引用、删除模式、范围是否含未来修订/重导入、抑制规则引用、control_seq、前链摘要和请求结果引用。不得把被删正文、可直接反推出正文的公开摘要或密钥塞进永久审计。

表达删除若原文保留，抑制绑定稳定 claim/source refs，防止重跑换 ID 再生。无法可靠识别同一断言时，保守抑制相关来源区间自动再提炼并显示范围；不能靠相似度猜测已删秘密。新独立证据是否允许形成新表达由删除模式明确；撤销抑制不恢复已擦除字节。

### 7.2 删除流程 D1–D7

| 步骤 | 操作与确认 |
| --- | --- |
| D1 验证与阻断 | M12 核对管理权限/目标范围；先阻断受影响的新读取、模型/导出出站与写准入。闭包尚不完整时扩大隔离到相关数据域/分区，不能先声称精确清干净。 |
| D2 独立持久意图 | 向不随普通备份回滚的控制账本追加完整意图并耐久确认；这是不可被主库回滚取消的点。失败不确认删除成功。 |
| D3 主控屏障提交 | 幂等应用墓碑/抑制、更新 control_seq、失效当前头/待办/packet 和缓存；形成清理 outbox。确认 blocked_from_use 需相关入口实际受屏障约束。 |
| D4 遍历依赖闭包 | 按反向依赖找源正文/附件、各历史记忆版本、合并结果、FTS/向量/图、出生准备/快照、DSH 原日志/摘要/引用/spill、调试渲染副本、受管导出与备份。其他模块的解释/理由也受相同来源限制。 |
| D5 后端清理与尾部核对 | 隔离或阻止旧写再次落入可用存储；逐组件回执包含目标代次/水位、处理对象、残留和在途尝试。清理后还可能有旧写时不能报最终物理完成。 |
| D6 重建可用派生物 | 混合来源摘要/合并记忆无法精确移除时，整体停用，从剩余合法证据新建版本；不能简单删除一个引用却保留其表达。图邻居/模型输入的间接依赖也须覆盖。 |
| D7 分阶段结束 | 输出“停止使用”“受管在线副本已清理”“备份待清理/不可修改”“外部已交付副本不可撤回”等实际状态；unknown 独立保留。 |

对只有追加日志且无可信清除机制的宿主，先封存/隔离旧 session，禁止恢复旧 prompt，按获准来源创建新绑定；另安排存储支持的清除。清除能力不确定时保持 copies_pending，不把 dispose 当日志擦除。

独立账本先写、主库未应用就崩溃时，恢复先重放；无法证明最新性时不读历史。删除/撤权水位不随着后端 generation、导入或重建回滚。

### 7.3 普通重启、旧备份与后端切换

普通重启沿 03 R0–R7：停自动入口→校验权威和最新控制账本→核对 pending/unknown→核验后端覆盖/映射→重建合法投影→按持久暂停意图开放。

旧备份沿 03 的额外来源恢复边界：快照里的 pending 不证明未执行；备份后事件/动作记录丢失时隔离不明新旧的输入。完整旧索引不能弥补缺失权威来源；缺口显式报告。

后端切换不等于旧备份恢复。权威数据未回滚时建立新 backend_generation：固定权威快照→受限重建→追赶连续增量→应用最新控制屏障→在短提交边界核对覆盖并 CAS active 指向。旧写只可落旧隔离代次，不能影响新代次。新后端故障后若回到旧后端，也必须补齐期间增量和最新屏障；不能直接翻回旧指针。单一可读写权威和 life_id 保持不变。

## 8 导出、导入与恢复流程

### 8.1 三种产物不能混称

| 类型 | 内容与用途 | 明确限制 |
| --- | --- | --- |
| memory-portable | 获准来源/记忆版本、来源链、范围/保留标记、必要 tombstone/抑制、映射和覆盖；用于换后端或受控迁移 | 不含正在执行的许可/凭据；缺身份/动作等系统状态时不是完整生命备份。 |
| life-backup | 03 所需的生命、业务/动作/待办、记忆及组件一致性 manifest；本适配器只提供记忆部分 | 不可仅靠插件 DB 宣称可完整恢复；还依赖最新独立控制账本与密钥管理。 |
| share-view | 当前授权允许交付的选定表达/证据 | 是披露后的副本，不可作为权威恢复包；移除内部秘密标识及未授权元数据。 |

权限规则可以随迁移包携带作限制，不能携带可执行授权令牌。未知主体/策略无法映射时数据隔离，不默认改成 global。分享包不输出原用户账号映射或内部删除账本；可恢复包只交给获准的可信目标。

### 8.2 ExportManifest 字段

export_id、format/schema_revision、kind、realm/lineage、snapshot_id、authority_commit_cut、created_at、授权目标、control_head_ref/应用水位、来源/记忆对象清单及摘要、附件引用与可用性、投影 generation/覆盖/缺口、依赖闭包说明、包含/遗漏类别、组件版本、完整性校验、状态和恢复能力声明。

manifest 不能把“快照时已应用的删除水位”当作未来恢复时的最新性证明；恢复必须另取当前账本。校验和只能发现内容变化，不自动证明来源可信、数据获准或快照最新。不能把密钥写进包；加密材料及解密/控制账本恢复条件单独管理，格式细节留到 M13。

### 8.3 导出 E1–E7

1. **E1 受理**：认证管理主体，明确类型、筛选、目标与可恢复范围；分配幂等 export_id。导出是数据出站，不因本机文件就跳过目的地和访问检查。
2. **E2 固定快照**：取得权威一致性快照和 commit cut，登记导出任务/依赖。后端若没有相同水位快照，可从权威快照生成可移植包，索引省略并明确可重建；不能直接复制正在写入的 DB/WAL 或目录冒充一致备份。
3. **E3 受限准备**：在只允许导出执行器访问的暂存区流式构造包。缺附件/来源或跨范围依赖明确记录；要求 full 的导出若缺必需内容则 blocked，不能偷偷变成完整度较低的包。模型不参与重写权威内容。
4. **E4 校验**：校验对象数、摘要、引用闭包、版本与水位、缺口和文件完整性。记忆副本可缺可重建索引，但不能缺失唯一权威内容后仍宣称等价迁移。
5. **E5 发布前复核**：核对当前授权和最新删除/撤销。导出期间出现相关删除时撤销 ready，清理暂存或重建受影响包；不能只按 E2 的旧策略交付。若范围未知则阻止发布。
6. **E6 受控发布**：发布/ReleaseExport 与撤销按 M02 明确顺序登记，使用绑定 export_id、目标和有效期的一次交付资格；实际文件权限/下载入口受控。崩溃或交付超时查询同一次交付，不另发第二份。已开始外部传输按 03 在途语义核对，不能声称可追回已输出字节。
7. **E7 后续管理**：记录受管包位置、依赖、交付状态、期限和清理进度。之后删除使受管下载资格/副本失效；已经交给用户或第三方的副本不能保证撤回，明确边界。

即使用户尚未点击下载，准备区/ready 包也属于可删除副本。后续目录搬移或过期清理不能绕过依赖登记；不把临时文件散落当作“尚未导出”。

### 8.4 导入/恢复 I1–I7

1. **I1 识别模式**：同一生命后端迁移、原生命备份恢复、外部历史材料导入分别路由。不同 lineage/life_id 不允许覆盖现有生命；外部材料成为新导入来源，不能伪造原生亲历。
2. **I2 隔离校验**：在禁自动处理区域解析格式、大小、对象引用与完整性；不信包内路径/账号/授权字段，不执行其中脚本或模型指令。未知必要 schema/含冲突对象则 blocked。
3. **I3 最新屏障**：取得独立控制账本最新性证据，并映射已有稳定来源/抑制身份；缺该证明的原生命恢复保持隔离。包内旧 control_seq 只供对照。
4. **I4 身份和版本映射**：同生命迁移保持 source/memory ID 和修订；已存在同键同载荷幂等，异载荷 conflict。外部导入用单独来源命名空间，保留原始外部标识/谱系映射；不能靠新命名空间绕过已知删除/抑制，无法判定则隔离待核对。
5. **I5 受限写入**：按 manifest 幂等准备来源/记忆与投影，应用 tombstone/抑制，报告缺口。导入不自动回复、累计成长或执行旧任务；出生选中试聊仍走 03 的确认快照/B5，不把整个试聊目录升级为正式。
6. **I6 激活核对**：验证覆盖、权限映射、最新屏障与旧写隔离；同生命迁移 CAS 切换 backend_generation，恢复旧备份还须新的 restore_generation 和 03 的来源/动作核对。导入成功不意味着全部自动执行入口开放。
7. **I7 保留退出路径**：记录迁移/恢复结果、原包和暂存副本清理状态；失败前保持旧有效指向，部分 staging 不可见。激活后的回退要追赶新变更并重新过屏障，不能撤销新的删除。

| MA05 | 相同请求重试或换 payload；换 request_id 重交同候选 | 同逻辑结果或 conflict；不重复版本、计数、强化、费用结算。 |
| MA06 | 领域提交后投影失败；后端成功但回执丢失 | 原事实已保存、索引待同步；核对同操作，不重新提炼或盲 learn。 |
| MA07 | 单条记忆拆块只完成一半；seq 后到先到 | 旧完整版本或 blocked；不暴露半版本，连续水位不越过缺口。 |
| MA08 | 删除后旧提炼/向量写回；旧 backend 仍存活 | 旧结果不能进入可用代次；残留/尾部未清时不报物理清除完成。 |
| MA09 | 删除表达但保留原文、重新提炼换 ID | 抑制仍生效；不因新 ID 复活表达。 |
| MA10 | 多来源合并摘要只删除其中一源 | 整体停用/重建并重算约束；不能删引用留泄露内容。 |
| MA11 | 删除意图持久后主库未应用即崩溃，恢复旧包 | 先重放最新屏障；缺最新性证明隔离；旧授权不自动恢复。 |
| MA12 | 查询翻页、缓存刷新期间撤权/纠正 | 旧结果/游标失效，最终模型出站也重核。 |
| MA13 | 导出构造中删除；ready 后撤销；传输后删除 | 未发布者重建/阻断，受管副本清理；已交付字节真实报告不可追回。 |
| MA14 | 导出缺唯一原文、附件缺失、插件库水位不齐 | full 要求受阻；partial 明确列缺口；记忆包不冒充生命完整备份。 |
| MA15 | 导入同键异载荷、未知策略、不同生命包 | 冲突/隔离，不覆盖当前生命、默认共享或触发历史动作。 |
| MA16 | 后端迁移后有新事实/删除，再回退旧后端 | 追赶增量和屏障后才准入；不回退删除，不重生，不漏新增事实。 |

这些场景扩充 03 C01–C32 和 04 G01–G10，不替代它们。后续证据须包含操作/尝试/版本/控制水位、真实后端写次数、可见结果和清理残留；本轮不运行。
