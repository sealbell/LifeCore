# LifeCore 设计梳理 04：记忆与上下文方案复用评估

日期：2026-11-02（Asia/Shanghai）。状态：P3 选型与适配建议稿；先设计，不开发。

承接：[01 基线](2026-11-02-design-baseline-and-responsibilities.md)、[02 职责与数据归属](2026-11-02-runtime-and-data-ownership.md)、[03 共同契约](2026-11-02-common-contracts.md)。事实依据见[固定版本源码证据](../../architecture/references/2026-11-02-memory-context-evidence.md)，其中 LM/SK/PL/DS 编号供下文追溯。

用户本轮授权是按共同契约比较复用边界，不是批准某个插件或开始实现。保留原有产品目标：共同经历、重要信息自动保留、用户可查看/纠正/删除、中文语义召回，以及独立的主动联想开关。不能因某个插件不支持就缩减这些目标。

后续细化：[05 记忆适配接口与数据字段](2026-11-02-memory-adapter-contracts.md)及[具体改动地图](2026-11-02-memory-adapter-change-map.md)已形成建议稿，补充来源/权限/幂等/删除/导出协议及更细源码定位，不代表最终选型。

后续选型收敛：[06 SeekMemory 服务与 PLUR 检索](2026-11-02-memory-route-selection-design.md)进一步比较最小接入、自研与维护，建议先复用 SeekMemory 候选处理组件并补齐受控中文语义召回；LifeCore 保留规范权威，不默认采用上游独立主库。该建议仍待确认。

## 1 结论与比较口径

**可以复用已有记忆算法和宿主机制，但目前没有证据支持把某个候选原样安装后，当作满足共同契约的完整记忆系统。** 最大的接入成本在来源、权限、写入、上下文失效和恢复边界，而非搜索函数本身。

| 分类 | 本稿含义 |
| --- | --- |
| 可直接复用（D） | 已有机制可原样保留，不需重写算法；仍要完成适配器接线、版本/依赖验证和验收，不等于整插件可直接启用。 |
| 需要适配（A） | 能力方向吻合，需补可信输入、字段映射、受控入口、生命周期或领域规则；区分外围适配与必须修改上游内部实现。 |
| 当前不满足（N） | 已有证据显示某条原样使用路径违背契约；禁止该路径直接接入，不等于项目永远不可用。 |
| 未核实（U） | 当前材料不足，必须保留待验证项；不能用“未找到”直接判定不存在，也不能视为已满足。 |
| 不承担（—） | 不属于该组件职责，须由 LifeCore/其他明确组件承担；不是该项目缺陷。 |

一个条目可同时包含 D 的底层机制与 A/N 的集成结论。所有判断限定[证据快照](../../architecture/references/2026-11-02-memory-context-evidence.md#1-核查快照)，不比较宣传功能数量或未经同条件测量的准确率。

## 2 三条可行性路线

| 路线 | 能省下什么 | 代价与判断 |
| --- | --- | --- |
| 整套记忆/生活框架接管 | 初期配置少，可同时获得提炼、召回、人格/维护 | 已读默认路径与多场景隔离、唯一提交和暂停规则存在冲突。当前不建议；不能同时保留两套独立人格和调度。 |
| 一个受控记忆后端＋DSH 执行/压缩 | 复用提炼、检索、索引、图、宿主会话及压缩基础设施 | **推荐继续评估**。LifeCore 保留共同契约；需接管所有入口，某些插件需要上游改动或受控分支，不只是包一层工具。 |
| LifeCore 自建记忆存储，仅借鉴算法 | 语义统一，摆脱候选的固有数据模型 | 初期开发与长期维护较多；作为候选接入成本过高时的退路，不提前启动。 |

推荐“受控复用”不等于已选 LivingMemory、SeekMemory 或 PLUR。后端最终选择须经过第 10 节门槛；当前不能负责任地估算节省百分比。

## 3 候选定位和复用清单

| 方案 | 可直接保留的机制 D | 需要适配 A | 当前原样路径不满足 N / 尚未核实 U |
| --- | --- | --- | --- |
| LivingMemory | 分词/FTS5、混合检索和排序机制；已有时间、图关联与诊断实现可选复用 | 可信场景、来源版本、受管提炼/夜巡、独立模型出站、去除竞争注入、导入/删除/恢复 | N：跨空间降权不是权限过滤；提炼缓冲不是持久接收账本；关闭自动召回不能关闭全部注入。U：隐藏出生准备、完整删除闭包及恢复证明。LM01–LM11 |
| SeekMemory | Source/Artifact 分层、版本与证据建模、候选查询/组装机制、提炼失败保留路径 | 只取受管记忆服务；更换普通全局池规则；统一提交/请求冲突、来源映射、受管模型和删除恢复 | N：默认普通全局池及完整 Runtime/人格接管不符合本路线；召回失败统一跳过不能覆盖权限故障。U：完整 LifeCore 出生/恢复接口。SK01–SK07 |
| PLUR | 混合检索与降级状态；显式 scopes 允许集合；独立配置开关 | 可信主体/场景映射；记忆语义和来源链；缓存失效、统一写入/删除、导出与恢复 | N：默认 global 加入、工作目录身份及可能使用旧缓存，不能当社交隔离方案。U：完整来源版本与备份控制协议。PL01–PL06 |
| DSH 会话/压缩 | 宿主日志、压缩范围替换/检查点、工具调用配对、压力计算与裁剪机制 | 受管摘要模型、生活摘要格式、来源依赖、取消/费用、删除重建、版本映射 | —：不承担长期事实/关系/人格权威。N：默认编程摘要不能充当完整生活记忆；只拦主循环会漏摘要出站。DS01–DS06 |

“直接复用”不承诺算法参数适合大肥鱼。中文同义、时间纠正、跨轮共同经历、误召回与长期保留仍须同数据评测。图关联只作候选，不自行形成新关系或成长证据。

其他已研究项目（MemoryCore、Hy-Memory、轻量 dsh-memory 等）继续保留在[原研究](../../architecture/references/memory-research.md)，本轮不把未重查的路径包装成与以上四项同深度的候选评审。没有理由同时安装多个记忆系统来“互补缺口”。

## 4 按六条共同契约逐项对照

| 共同契约 | LivingMemory | SeekMemory | PLUR | DSH 与 LifeCore 的分工 |
| --- | --- | --- | --- | --- |
| 出生 B1–B6、K01/K10 | U：未证明确认快照/隐藏准备/manifest 激活；A：源码内部管道也必须看出生资格 | U：已有 Source/Artifact 不等于出生准备协议；A：不能让 Dream/人格提前读取试聊 | U：scope 不等于隐藏准备；A：关闭自动学习也要限制工具和缓存 | LifeCore 持有唯一出生提交；候选只能准备被选择材料。普通 DSH session 不授予正式身份。 |
| 接收 K02/K03 | N：截断、延迟落盘和缓冲淘汰不能承担 accepted；D/A：可作持久事件之后的派生任务 | D：事务内来源写入；A：请求载荷冲突与 reply job 共同提交仍需补 | —/U：自动纠正/轮尾情节不替代平台来源账本；需受控摄入协议 | LifeCore 原子接收事件＋待办；宿主日志按 dispatch 关联，不能靠两个插件各听一次事件保证一致。 |
| 执行绑定 X1–X6 | A/N：cwd/session 空间和全局钩子不能直接映射生命/场景；所有 host 路径须受控 | A/N：DSH bridge 含自己的 Runtime 与人格刷新，不原样挂到正式执行链 | A：scope 映射及缓存按生命/场景/代次校验，不能只认目录/agentId | DSH 提供执行载体；LifeCore 激活绑定并管理旧 inbox，记忆适配器不能自行创建有资格的对话。 |
| 授权 K04/K06/K08 | N：降权与 global 兜底不满足检索前过滤；A：所有查询、回查、提炼及外发端点纳入许可 | N：普通全局池后披露不满足前置权限；A：在全部候选/原文回退/图路径之前限制 | D：scopes 机制；A：可信授权映射、撤销/缓存失效及端点核查；N：默认 global 不是共享许可 | M12 统一授权；摘要也是模型出站。失败须区分可选检索降级与权限/删除不明而阻断。 |
| 动作/回执 K05/K09 | A：助手文本和 todo done 不能作为平台成功；工具写入和后台维护须关联已提交结果 | A：记忆使用统计、Runtime 记录与真实外发分开，不能在生成或注入时认定已说过 | A：autoCapture/feedback 与已发送回执分开；写入超时不能直接当未生效 | M11 独占外部效果结果；记忆只投影已核验事实。查询、注入、生成、发送各记各的状态。 |
| 暂停/恢复 K07/K11/K12 | D：维护标记/定时器清理可用；A/U：覆盖全路径、异步尾部、独立删除账本和恢复水位 | A/U：受管任务停止、独立控制账本、来源缺口与旧效果核对 | A/U：停止入口不保证超时写已停；等待/隔离旧写并重建缓存、核对删除与水位 | LifeCore 先屏障后恢复；DSH 原日志、压缩摘要、引用快照都在清理/失效范围。 |

恢复的共同底线：旧备份缺失接收/动作记录时，即使记忆库可打开，也不能把重送当新输入自动回复、整理为新经历或累计成长；沿用 03 的来源恢复边界。一次“重建索引”只能还原派生物，不重放外部动作。

## 5 LivingMemory：具体怎样接入才可能成立

### 5.1 可以保留什么

可保留其分词、全文索引、候选排序、时间字段、图关联算法及部分统计机制。重要性、衰减和夜巡规则只能作为候选策略，不能默认删除 LifeCore 已承诺保留的来源，也不能直接修改 M05/M06/M07 的权威状态。读取 API 名称“只读”不代表没有用量统计、强化或其他写副作用，需逐项列出。

### 5.2 不是改几个开关就能解决的地方

| 入口 | 已读行为 | 计划中的处置 |
| --- | --- | --- |
| host/write 角色 | write 工具与 host 内部管道分开 | 不把撤掉 write 当作停写；正式接入必须覆盖 host 的观察、提炼、后台和模型调用。 |
| systemPrompt.context | 独立注入常驻待办/事实等材料 | 由 M09 单一装配；不能仅关 LEGION_AUTORECALL_OFF；必要时需要修改挂载实现。 |
| system-prompt/assemble | 自动召回及短期缓存 | 关闭竞争注入或转为只返回结构化候选；缓存依赖包含来源/策略版本，撤销时立即失效。 |
| session/event | 观察、缓冲、工具结果与压缩桥 | 从 LifeCore 已提交事件供给受管任务，或只把宿主事件当可核对旁证；不能兼作第二接收权威。 |
| search/回查/图邻居/时间线/诊断 | 存在不同查询路径及跨空间逻辑 | 检索前统一允许集合，模型只可缩小查询；不能先全库检索/外部 rerank 后在返回结果处过滤。 |
| 提炼、spoken-prefix、预裁、embedding/rerank | 多套独立凭据/端点路径 | 每次请求使用受管模型网关和材料范围、预算/attempt；不能仅代理主聊天调用。 |
| 夜巡/压缩桥 | 定时与异步写入 | 改成有任务 ID、依赖版本、提交许可和恢复记录的受管整理；宿主压缩不等待无保证的提炼回调。 |

这些改变中，可信过滤、全部注入/后台入口接管可能触及 index.cjs 内部，不应估算成普通外围包装。若必须长期维护大范围分支，须与其他后端重新比较总维护成本。未完成前，不提供一份看似可安全上线的安装配置。

### 5.3 明确不能直接承诺的能力

- 仅凭 space 和 global 不能承诺私聊/群聊/试聊不串数据。
- 仅凭 SQLite、checksum、extract_buffer 不能承诺每条 accepted 消息和回复待办不丢。
- 仅凭 source 会话字符串、read_episodic 不能承诺每个断言都有精确来源修订。
- 仅凭 deleted 过滤、缓冲墓碑、数据库备份不能承诺删除后恢复旧备份不复活。
- 仅凭夜巡和图谱不能承诺符合大肥鱼的共同经历、人格成长或中文长期记忆质量。

前三项有明确原样路径冲突；删除恢复完整性和质量则是未核实门槛，不能混写成“已证明完全没有”。

## 6 SeekMemory 与 PLUR 的替代价值

**SeekMemory 更适合继续核对“记忆服务组件”复用。** Source/Artifact、版本、提炼阶段和查询结果元数据接近我们的证据需求，但普通全局池须替换，Runtime/Dream/人格不能成为第二权威。优先核对不挂完整 DSH bridge 时是否能独立使用服务与调用方事务；原文回退、关系轨迹、置顶与图传播都要执行相同范围限制。不能仅在最后生成的文字上做隐私处理。

**PLUR 更适合继续核对“检索组件和受控记忆条目”复用。** scopes 允许集合、独立自动功能开关和检索健康模式是有利条件，但还需来源版本、共同经历表达、出生准备和删除恢复契约。includeGlobal=false 是减少默认共享的配置，不是完成社交权限设计；多个场景处于同目录时仍须由可信映射隔离。异步刷新缓存不能保证本轮读到刚发生的纠正，必须有即时失效和必需事实查询路径。

两者均不能因模块名叫 Memory 就自动获得全部 LifeCore 数据。当前不根据这轮局部阅读排序“谁记忆最好”，也不预先选择开发语言或物理数据库。

## 7 数据权威：推荐一个受控派生后端

### 7.1 两种权威方案的取舍

| 方案 | 语义 | 当前建议 |
| --- | --- | --- |
| 后端作为某类记忆唯一权威 | 当前记忆只在后端修改，LifeCore 保存引用/来源和命令结果 | 可减少内容副本，但要求后端原生支持全部版本、命令幂等、导入、删除与恢复接口；当前证据不足，保留备选。 |
| LifeCore 领域记忆权威＋后端派生服务 | 来源、当前事实/经历版本和人工覆盖由 M03/M04 控制；插件提炼产生候选，检索索引/图为可重建派生物 | **推荐作为后续设计前提，待确认**。只维护一套可修改的当前事实，派生副本不能反向自立为权威。物理数据仍可委托同一后端存储，不强制双数据库。 |

选择派生路线也有自研成本：M04 必须定义事实/经历/来源版本和提交规则，不能只剩一个空壳。节省的是检索、索引、部分提炼/维护和宿主基础设施，不是免除领域契约。

### 7.2 拟议的适配操作

以下是后续接口设计的语义名称，不是现有插件 API：

| 操作 | 输入 | 输出与提交规则 |
| --- | --- | --- |
| PrepareImport / QueryImport | birth operation、已确认材料、源版本、受限命名空间、幂等键 | 持久准备引用；正式读取/后台不可见，LifeCore 出生清单提交才可开放。 |
| ProposeMemory | 已提交来源区间、目的、允许模型端点、当前版本与预算 | 带逐断言来源的候选；M04/M02 校验提交。不能调用插件直接覆盖当前事实。 |
| ApplyProjection / QueryProjection | 已提交记忆版本/墓碑、operation ID、目标索引代次 | 后端幂等应用并返回可核查水位；控制层 outbox 补偿，不假装跨库事务。 |
| Recall / ReadEvidence | 可信允许集合、查询目的/时间、覆盖要求和预算 | 结构化候选/来源片段及版本、冲突、缺口、健康状态；最终使用前再查屏障。 |
| Invalidate / Erase | 删除或撤销水位、来源依赖闭包 | 先停用，后报告各副本清理进度；禁止索引重建/出生快照恢复已删除材料。 |
| Export / RestoreCheck | 生命谱系、格式、来源/记忆/投影水位、控制账本证明 | 可核对 manifest 与缺口；换后端不换 life_id，不能启动旧任务。 |
| Pause / ResumeMaintenance | 受管任务、运行代次、持久暂停意图 | 停止新许可，核对在途写/费用；恢复前核对取消与删除。 |

插件内部维护的技术数据（缓存、索引、统计）可自行持久化，但其写入必须处于受管范围。若内容合并/遗忘改变业务事实，必须返回候选经过唯一提交；不能借“派生维护”静默修改事实。

## 8 上下文：复用 DSH，但由 M09 决定材料

### 8.1 四类数据各有用途

| 材料 | 权威与用途 | 不能替代 |
| --- | --- | --- |
| M03 获准来源与实际回执 | 可追溯的发生事实和来源修订 | 不能被摘要写成不同事实 |
| M04 事实/共同经历表达 | 带来源的长期可查询记忆 | 不代替人格/关系/动作权威 |
| M09 工作摘要/ContextPacket | 当前场景连续性、未完事项、材料选择与预算记录 | 不是独立的新经历或权限证明 |
| DSH session surface/压缩检查点 | 模型执行窗口及可重放投影 | 不承担生命身份和唯一长期记忆 |

### 8.2 一轮材料进入模型的顺序

1. 从 03 已接收事件和有效绑定得到可信场景、当前授权与删除水位。
2. 准备必需的当前事实、未完任务及原始输入；主动联想开启才增加话题相关经历候选，显式回忆仍按目的查询。
3. 对允许候选执行索引/检索，记录来源修订、覆盖和错误状态；不能让后台插件悄悄提供另一套全局材料。
4. M09 去重并划分预算，生成本步 ContextPacket 记录：来源 ID/版本、授权版本、绑定代次、当前事实/任务版本、材料类别、取舍理由及覆盖缺口。
5. DSH 在预定受控边界刷新本轮材料。最终请求与 packet 对照；主对话、工具读取、摘要和维护调用分别检查出站许可与预算。
6. 删除/撤销/纠正到来时，失效相关 packet、缓存和受影响摘要。摘要无法追踪细粒度依赖时，按整个覆盖区间失效并从仍获准来源重建；不能只让下一轮索引看不到旧条目。
7. 回忆是否真的被提及由生成候选和成功回执关联记录。检索、注入、重试、摘要重建不增加独立经历次数。

主动联想开关不关闭记忆保存、不关闭显式回忆，也不等同任何候选的 autorecall/injection 全局开关。关闭时不得从常驻事实块或旧缓存绕回自发联想；必要的当前状态和显式问答按各自目的保留。

### 8.3 压缩策略的推荐与退路

推荐复用 DSH 压缩事务、工具配对、压力计算和原日志关联，适配其 summarize 扩展点；不再对同一范围并行执行 LifeCore 自建滚动摘要和另一套插件压缩桥。

需要适配的摘要内容：参与者/场景、已知与未知、当前话题、来源区间、未完承诺和动作状态、纠正/撤销依赖、继续工作的检查点。人格/关系/任务的当前权威状态在每次恢复时重读，不能只信旧摘要。摘要不可写成“发送成功”来覆盖未知回执。

摘要模型调用纳入独立受管任务/许可，检查实际重放的 system、工具声明与历史材料；不能只拦 agent/request，因为此版本基础摘要走直接 llm.stream。换摘要端点不自动继承资料出站权限。输出保留出处与覆盖，压缩失败保留可诊断旧状态，不假造成功。

压缩不是“记忆提炼已经完成”的证明。允许先完成压缩的前提是相关获准原始来源和整理待办已经耐久保存、后续提炼能按同一来源区间读取；不满足时先阻断或缩小处理范围。宿主原日志若尚未可靠持久，不能独自充当此前提。

工具结果裁剪可复用，但明确省略并能受控回查。session-reference 的跨会话预览、完整快照及 spill 副本都要纳入授权与删除闭包；不默认开放所有会话引用。

若目标发行版无法受控替换摘要调用，或不能对删除后的旧日志/摘要防止再次使用，则该压缩路径暂不准入。可用经过核验的授权历史创建新绑定完成工作段交接，仍须 03 的尾部、待办和未知动作核对；不能偷偷恢复旧版“每轮重开”或固定 70% 门槛。具体容量参数在实际模型和材料评估后确定。
