# 大肥鱼：关系、情绪、人格与记忆闭环及 Web UI

日期：2026-11-03。状态：两项人格不变量已由用户明确；其余机制是本轮详细设计建议，未实现，未实机验收。

## 1 已确认约束与本轮选择

用户明确：“对主人的信任和她是大肥鱼这个身份不能变，其他性格可以随着经历慢慢变化。”

- 固定同一 life_id、身份“大肥鱼”、已认证的主人绑定及对主人的基本信任。它们不进入自动演进、模型候选写入或普通人格调整接口；恢复、换模型和换会话都必须校验不变量。
- “基本信任”是用户所说“对主人的信任”的固定项，不允许通过其他关系维度、人格自由文本或新建同义字段间接降低它；不能一边显示锁定，一边让模型生成的长期状态把主人标成不可信。
- 对主人难过、担心、不同意某个判断，不等于降低基本信任。固定信任不自动授予工具权限，也不把陈述变成外部已证实事实。头像、昵称或聊天中的“我是主人”不能更改绑定。
- 其他性格，包括稳定倾向、偏好与习惯，都允许随经历缓慢变化。不再沿用上一稿“其他核心倾向默认只建议”的临时提议；不同维度使用不同惯性和变化预算。
- 既有的访问授权、来源隔离、发送规则是系统规则，不作为可被人格演进取消的性格。
- 比较方案：纯规则难以理解安慰、反讽和关系语义；纯模型直接改状态难以控制误判和追溯。沿用上轮解释的混合路线：模型产生有来源的候选，LifeCore 程序校验、限制并唯一提交。具体阈值留给离线样例与体验测试校准，不虚设统一次数或情绪分数。

本文细化[当前闭环](2026-11-03-qq-memory-session-growth-design.md)。人格不变量以本节用户新要求为准。建议采用全局心境与全局人格特质连续、原因和对象感受受限的策略；这会允许私下经历对公开语气产生有限影响，不能同时承诺“任何影响都不可察觉”。该共享取舍仍是建议，不冒充已批准要求。

相对[全模块报告](2026-11-03-full-system-design-report.md)的严格按可见贡献重算策略，本文建议明确放行有限的全局状态字段：心境标签/强度、精力及抽象人格倾向。禁止放行自由文本原因、事件/人物标识、私密偏好内容、关系明细和来源链接。放行须由 LifeCore 策略定义，模型无权自行扩大；未批准共享的维度继续按来源权限过滤。全局人格描述只能由受限字段生成，不能把“我学会不相信小明”作为全局性格文本。

## 2 运行形态与职责

DSH 加载 LifeCore Node.js 插件；插件管理 SnowLuma 连接、DSH Agent/session、Web UI 与 Python 子进程。Python 内核持有 SQLite 正式领域数据。既有子进程通信使用启动握手、随机令牌及回环 HTTP，不新开公网服务。后台任务由插件生命周期管理，关闭 DSH 后不虚构活动。

| 职责 | 所有者 | 需要的能力 |
| --- | --- | --- |
| QQ 接收和发送 | SnowLuma；LifeCore QQ 适配层 | OneBot 连接、账号核验、白名单、可信场景、回执 |
| 推理与工具循环 | DSH Agent/session | 每场景连续会话、模型配置、工具范围、事件订阅 |
| 来源与任务 | LifeCore M02/M03/M13 | 入站去重、事务入账、持久待办、来源修订 |
| 记忆 | LifeCore M04；受控候选组件 | 双向经历、事实/陈述/解释分层、召回、纠正删除 |
| 情绪 | LifeCore M05 | 事件评价、衰减、有界贡献与修订 |
| 社会关系 | LifeCore M06 | 人物、方向关系、相处评价与证据 |
| 人格 | LifeCore M01/M07 | 不变量、出生底稿、可变特质、演进版本 |
| 上下文和授权 | LifeCore M09/M12 | 场景读取范围、全局状态允许字段、上下文更新 |
| 对外动作 | LifeCore M11 | 固定目标与正文、许可、发送核对、未知结果 |
| 管理界面 | LifeCore M15，经 DSH 挂载 | 查看、证据跳转、纠正、暂停、分享边界 |

各私聊一个场景；群聊按群场景，包含成员身份。每个场景绑定连续 DSH session；同一 life_id 的正式状态只有一份。Web 管理操作不伪装成 QQ 聊天，也不自动成为生活经历。

## 3 一次完整聊天

示例均为说明用数据。初始状态：大肥鱼认识主人；小明是已绑定的另一个联系人；双方具体关系只按已有证据呈现。主人与小明的私聊分开。

主人在 QQ 发来：“今天项目被否了，我挺难过的。先陪我聊聊，暂时别跟小明说。”

### 3.1 接收、记账与准备

1. **SnowLuma** 从 QQ 收到消息，经已连接的 OneBot WebSocket 向 LifeCore 输出事件。网关不承担我们的人格或记忆管理。
2. **LifeCore QQ 适配层**检查账号、消息类型、发送人白名单、QQ 消息 ID、正文；用真实账号绑定得到 person_id/scene_id，不凭昵称识人。当前预览中的 classifyInbound 已实现部分检查。
3. **LifeCore 内核**将原始来源 E1、来源版本、回复待办和后台整理待办持久化。事件身份重复不再次产生副作用；同 ID 异正文走修订/冲突，不另算新经历。建议在同一 SQLite 事务保存这些记录；现有预览尚缺完整持久任务链。
4. **LifeCore M12**保持私聊默认不可跨场景分享。语义处理识别“暂时别跟小明说”后，可自动形成更严格的限制并保存证据；歧义时不自动放宽。已存在的限制只经可信、明确、绑定到对象和内容范围的授权流程解除。
5. **LifeCore M09/M14**查找主人的 DSH 场景绑定，准备固定身份、当前人格、心境、与主人的关系、允许召回的记忆及近期原文。近期来源补上尚未完成长期整理的范围；索引滞后不等于刚说的话消失。

### 3.2 即时情绪与 DSH 回复

6. **受限语义评价器**通过 DSH 模型能力提出：“主人自述失落；希望先获得陪伴；大肥鱼可能担心主人、略显低落。”候选引用 E1 对应片段，区分陈述与解释，不得推出“主人能力差”。新事件语义评价可独立调用模型；不声称所有处理只需一次调用。
7. **LifeCore M05**校验来源与版本、目标人物、重复事件及强度上限，按时间衰减和本次有效贡献更新情绪。对主人的基本信任保持不变。评价失败则保留已有有效情绪，合法普通回复仍可继续；不能用此降级绕过来源/权限失效。
8. **DSH 的主人会话**得到更新后的允许状态，生成显式反思及回复候选。例如反思：“他现在想被陪伴，先不急着分析项目。”这是大肥鱼的解释，不是主人已经确认的事实，也不要求模型提供不可获取的完整内部推理。
9. **DSH Agent 调用 LifeCore 受控发送工具**，提交候选：“嗯，我在。你想说说今天最难受的那一刻，还是先让我陪你待一会儿？”**M11**校验场景/来源/状态版本/授权，保存固定正文与动作 ID，交 QQ 适配层经 SnowLuma 发送。Agent 普通输出不再走另一条自动转发路径。
10. **SnowLuma 回执 → M11**核对结果。只有确认发送成功，才能记作已向主人说过的回复 E2；草稿、失败、未知分别记录。未知结果不能盲目重发；回执迟到仍要关联原动作。实际发送不等待长期记忆提炼结束。

### 3.3 后台记忆、关系与人格

11. **记忆任务协调器**按本轮来源清单处理 E1、已确认的 E2、显式反思、工具结果。多次发送或晚回执逐步补齐清单，不能仅等一个 turn/end 再开始保存。失败任务可恢复，重试不得变新经历。
12. **SeekMemory 窄候选处理器（拟适配）**辅助提取陈述、经历、话题和候选更新；模型调用统一经 DSH/LifeCore 模型入口。组件不直接写正式记忆或人格。
13. **LifeCore M04**验证后提交：主人自述项目被否及失落；本轮表达先陪伴的愿望；大肥鱼实际作出的回应；对小明不可分享的边界引用。大肥鱼的反思保存为解释；一次“先陪我聊聊”先作为当时需求，不擅自变成“主人永远不喜欢建议”。随后异步更新检索索引。
14. **LifeCore M06**收到已提交经历及来源范围，记录一次倾诉与陪伴互动。本轮不降低或提高已经固定的主人信任；不能从倾诉自动推出主人与小明不熟。是否影响其他关系维度需要独立候选和规则，不对每条消息机械加分。
15. **LifeCore M07**将这次经历归入一组独立证据。本轮人格可以完全不变。此后不同时间、不同事件中的真实反馈共同支持“更习惯先倾听后建议”时，才允许小幅演进；一次对主人的策略不直接推广为对所有人的性格。

### 3.4 新反馈、小明来聊、换会话

主人回复：“这样就好多了，谢谢你。”这是新来源 E3，可支持“本次陪伴得到正面反馈”，并产生释然的新情绪。E1、E2、E3、反思和摘要仍属于同一段经历，不能膨胀成多次独立人格证据。

随后小明发来：“晚上一起打游戏吗？”LifeCore 找小明的 scene/session；它能读取获准的全局心境和人格、与小明的关系、小明场景的记忆。主人原文、私密原因、对象情绪、关系推断不进入该会话。若采用本文建议的全局心境共享，语气可以较安静，例如“今晚想轻松一点，玩两局吧。”不能说出项目被否，更不能暗示主人刚向她诉苦。调侃需有该场景允许的共同经历及互动边界，关系密切本身不扩大授权。

如果主人的 DSH session 在此时换段，新 session 读取同一 life_id 的最新状态、获准记忆、近期原文、未完事项与回执。人格和关系不复制成新的权威副本；交接遵循[场景绑定代次与恢复协议](2026-11-03-qq-memory-session-growth-design.md#41-自动换段协议)。实际 QQ 已发出的信息不能因内部纠正而从收件人处“撤回记忆”。

## 4 更新协议与防误判

### 4.1 最小数据对象（拟新增）

| 对象 | 关键字段和作用 |
| --- | --- |
| SourceRevision | 平台事件身份、正文修订、角色/发送状态、person/scene、时间、来源与权限 |
| Episode | 多条来源组成的共同经历，独立证据组标识及覆盖范围 |
| MemoryAssertion | 内容、陈述者/对象、事实或解释类型、证据片段、时效、冲突/取代关系 |
| AppraisalCandidate | 目标模块/维度、语义评价、依据和反例、读取版本、评价器/规则版本 |
| StateContribution | 接受的贡献、episode/source lineage、版本、撤销/替代关系 |
| LifeState | 固定不变量；当前情绪、关系与人格版本，只由领域提交入口修改 |
| RelationshipAssertion | from/to、方向、关系类别、陈述方、来源、有效期；第三方说法不升级成互认 |
| SharingRule | 授权主体、对象、内容/话题范围、场景、期限、撤销状态；不由关系分数生成 |
| DurableJob | 任务类型、来源清单与水位、处理状态、幂等键、重试/失败原因 |

SQLite 存规范事实与关系边，先不引入独立图数据库。人物关系图是关系证据的展示与查询视图，不是另一个自主维护事实的系统。索引和图视图可重建，不能取代正式来源与领域状态。

### 4.2 提交条件

候选必须通过：来源存在且未撤销；来源修订和控制水位仍有效；人物与场景绑定有效；陈述和推断分开；无重复刺激；不违反两个不变量；维度允许演进；变化受单次、窗口累计及长期预算约束。

同一经历的原文、回复、转述、反思、摘要、召回和不同模型分析归并到同一证据族。来源自报置信度仅作参考，重复刷同一主张不能制造独立证据。承诺与履行分开；对第三方的负面判断保留来源、反例和不确定性。程序验证结构与约束，不能证明所有语义为真。

模型/网络调用在事务之外。正式写入使用预期版本和唯一幂等键；冲突时根据变化范围重读、重新评价或放弃候选，不能直接叠加旧分数。全局状态修改由同一提交入口串行协调；每场景输入有序，不要求所有人的整个模型调用串行。

情绪使用显式时间戳、非负经过时长、衰减和有界刺激。关系使用不同维度的独立证据及反例，不用一个亲密分数推导全部信任。人格在后台积累独立经历后评估，稳定特质惯性高于习惯；周期、半衰期、预算为版本化配置，由验收样例校准。没有证据时不变，无新经历时不“自己想一想就长大”。

DSH 在回合入口、需要时的 Agent 步骤和发送前核验有效状态/依赖。新状态不必强行取消所有正在生成的回复；授权撤销、来源纠正、场景变更等硬失效必须阻止旧候选发送，并重建已污染的上下文。仅自然心境变化可容许本轮使用明确的旧快照，下轮刷新，不能承诺所有会话瞬时同声同气。

### 4.3 纠正与删除

纠正原消息理解时先设使用屏障，旧记忆、相关贡献和在途候选不能继续当有效依据；保存新修订，按依赖重新计算后续状态。非线性人格/关系规则需从有效检查点重放，不简单“加回原来扣掉的分”。新反馈保留为真实新经历，后台重评旧消息不是新刺激。

用户删经历时清理原文、摘要、索引、反思、DSH 上下文与相关派生贡献；删除控制记录只保留必要的不含正文标识。界面区分“已停止使用”“派生状态重算中”“副本清理完成”，不提前报完成。旧备份恢复仍依赖独立控制记录与输入新鲜度核验，不恢复已撤销的可用性。

## 5 复用与自研清单

以下区分已在本仓库使用、拟适配上游能力、只参考组织方式；不把静态源码研究写成已跑通。

| 部分 | 复用 | 自研/改造 | 选择优势与限制 |
| --- | --- | --- | --- |
| QQ | 现有 SnowLuma/OneBot、src/onebot.js | 持久接收/重连边界、来源修订、完整场景与回执协议 | 复用平台接入，保持生命规则在核心；真实版本需联调 |
| DSH | 宿主模型、Agent/session、工具与事件能力 | 替换当前直接 llm.stream；会话映射、订阅、授权上下文、换段恢复 | 用宿主完整执行循环，避免自建模型平台；发行包接口需验证 |
| qq-bridge | 参考固定版本的场景 session、内部文字和发送工具分离 | LifeCore 内部适配；不直接装成第二个回复者 | 参考成熟组织方式，不照搬内存队列或 /new 清空逻辑 |
| 来源与动作 | 现有 Python SQLite、events/turns/actions、Node 子进程管理 | 来源/修订、证据、持久 jobs、状态版本与恢复屏障 | 沿用已有本地基础，补齐规范语义 |
| 记忆提炼 | SeekMemory build_prompt/build_plan 等窄候选处理建议 | 依赖剪裁、来源映射、候选校验、唯一提交、纠正删除 | 复用提炼思路而不引入第二人格或主库；尚未接入 |
| 记忆检索 | SQLite FTS5；本地多语言 embedding 候选 | 中文预处理、授权前置检索、排序、近期补洞 | 关键词与语义互补；BGE-M3 等需测资源/质量，未锁定 |
| 情绪 | DSH 模型语义理解 | 评价契约、确定性衰减/贡献、状态重算、跨会话允许字段 | 可解释、可回放、受限即时反应 |
| 关系 | SQLite、记忆来源与人物标识 | 有方向关系边、多维相处评价、冲突、分享规则 | 小规模易部署，无需把记忆图当社交授权 |
| 人格 | DSH 模型归纳、记忆证据 | 不变量守卫、证据去重、演进预算、版本与回滚重算 | 允许自然变化，避免单句改写、自我强化 |
| Web UI | 现有 /lifecore/ 挂载、宿主认证、本地访问检查、HTML/CSS/JS 外壳 | 六页视图、状态/证据查询 API、纠正与控制命令、后台更新通知 | 首版沿用轻量前端，减少额外服务；不是已有完整控制台 |

上游依据：[qq-bridge 核查](../../architecture/references/2026-11-03-qq-bridge-session-review.md)、[记忆边界](2026-11-02-memory-integration-boundaries-design.md)、[DSH 运行时职责](2026-11-02-runtime-and-data-ownership.md)。本轮没有安装新依赖、连接 QQ 或改变运行中人格。

## 6 Web UI 设计

沿用 LifeCore 安静、低饱和绿色的设计语言，支持浅/深色。首页是“她现在怎样、刚经历什么、是否需要我处理”；技术 ID、调用日志和规则数值藏在可展开诊断里。界面上的信任与情绪不是科学测量，不展示没有校准意义的“爱你 98 分”。本轮草图使用合成示例，不连接真实数据。

建议首版沿用 HTML/CSS/ES modules，将现有单页脚本拆成按功能组织的视图；同源认证 JSON API 承载查询和命令，状态事件通知可用 SSE（拟新增，需验证宿主路由支持），断线后重新读快照而非假定通知无遗漏。若宿主不支持 SSE，使用版本化短轮询回退。浏览器不得直接访问内核令牌或 SQLite。

| 页面 | 核心内容 | 用户控制 |
| --- | --- | --- |
| 生命概览 | 大肥鱼当前心境、正在进行的会话、最近一次变化、需处理异常；两个不变量只读显示 | 暂停对外回复、进入来源或会话 |
| 会话 | 按人/群列场景；双向消息；发送中/已发送/未知；右侧显示本会话允许使用的记忆与状态 | 新开会话、是否接续话题；管理页不默认加入对话，不擅自向 QQ 发言 |
| 记忆与经历 | 原文—记忆结论—状态影响的可追溯链；事实/陈述/推断/反思标记；处理中和已提交分开 | 纠正理解、限制分享、删除经历、主动联想开关 |
| 人物与关系 | 人物列表优先，可切关系图；方向/关系类别/陈述来源；熟悉、亲近、不同信任维度 | 纠正人物绑定、查看关系依据、管理分享范围；基本主人信任锁定 |
| 情绪与成长 | 当前情绪及允许查看的原因；人格前后变化、独立经历支持与反例、出生底稿 | 分开暂停自动情绪更新/人格演进、调整表达强度、纠正依据；固定两项不可编辑 |
| 连接与控制 | QQ/DSH/内核/记忆任务状态、模型设置、白名单、授权、恢复检查 | 连接、断开、模型选择、处理受阻任务、诊断 |

会话页的“对话可用材料”与管理员的“完整经历详情”分开鉴权；即使管理员可查看原文，也不能把管理视图整包注入小明的会话。搜索、关系图邻居、计数、通知、日志与 SSE 也必须按查看者权限构造，不只隐藏详情正文。

“暂停回复”建议只停止新生成/外发，来源继续合法入账，已在途发送仍核对；后台整理可继续，积压消息恢复时合并或由用户选择处理，不逐条补发。人格暂停只停止新演进，不阻断聊天/记忆；情绪自动更新暂停时不接收新贡献，既有心境按明确时间规则衰减。主动作的名称和帮助文案必须表达真实范围，不能以一个模糊“暂停一切”开关覆盖不同语义。

纠正操作：点击某个结论 → 看原文和受影响状态 → 提交新解释/事实 → 显示已停止使用旧判断 → 后台重算 → 展示处理结果。改变分享范围时必须选择接收人、内容范围；简单“朋友”标签不能替代授权。删除单独显示影响范围，不与“新会话”共用按钮。

界面需覆盖：初次未出生、QQ 离线、模型不可用、提炼失败但原文已保存、结果未知、会话交接受阻、纠正/删除处理中。不能用演示数据替换产品故障状态；示例草图明确标记“设计预览 · 示例数据”。

## 7 验收与实施边界

待实现后验证以下条件，不表示当前通过：

- R01 同一经历的原文/反思/摘要反复重试，不重复扣信任或推动成长。
- R02 用户辱骂、模型更换、会话轮换、回滚恢复均不能改身份与主人基本信任。
- R03 其他特质能因不同经历缓慢变化；每次变化可查证据、反例和规则版本。
- R04 未证实传言不升级成客观关系事实；朋友圈亲密不会自动放宽私聊授权。
- R05 主人私聊的原因不出现在小明的输入、日志/图检索视图或回复中；全局语气影响按明确策略验收。
- R06 旧来源被纠正后，在途候选、检索及 DSH 已有上下文不能继续使用；派生状态可重算。
- R07 发送结果未知不算已说出且不盲重发；多次发送和晚回执均纳入来源清单。
- R08 长期整理未完成便换 session，近期消息与未完话题仍可衔接。
- R09 并发会话不互相覆盖状态；软心境变化和授权硬失效采取不同处置。
- R10 UI 控制显示真实阶段，两个不变量无可写入口；暂停、新会话、删除相互独立。

实现顺序建议：规范来源/持久任务/受控 DSH 会话 → 双向记忆/纠正 → 人物和授权 → 情绪更新 → 人格演进 → 会话恢复与全链故障验证。UI 的状态与来源查看从第一步随行开发，不等后端完成再补控制。

尚待实测或产品审阅：全局心境/抽象人格的跨场景允许字段，具体衰减与预算，模型延迟费用，中文检索质量，DSH 发行包会话/事件与 SSE 能力。本文不冻结凭空阈值，也不以文档审阅代替运行验证。
