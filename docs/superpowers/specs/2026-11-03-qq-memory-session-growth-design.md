## 1 本轮交付的体验

大肥鱼可以通过 QQ 与用户持续交流，记住共同经历；即使模型上下文换段、宿主重启或模型更换，仍认识当前对象、知道刚才聊到哪里；当前经历能引起可解释的情绪变化，长期独立经历能推动有惯性的人格演进。用户能查看、纠正、删除和暂停相关行为。

建议第一条真实验收链使用已绑定主人的一个 QQ 文字私聊，网关沿用已确认的 SnowLuma。其他人物/群场景先作为隔离反例，不要求这一轮一起交付完整群聊功能。正式多联系人范围仍待确认；数据结构不能假定所有消息都来自主人。

必要基础仍包括 M01 身份、M02 协调、M03 经历、M06 人物/关系最低状态、M11 回执、M12 权限、M13 存储与 M14 宿主；M15 只提供此闭环所需控制页。M08 暂不做完整生活活动，仅保留必要的对话未完事项，不引入主动观看、工作或社交调度。

## 2 路线与当前建议

同日后续澄清：用户要求将大肥鱼自己的思考与回复纳入记忆，并重新参考 qq-bridge 的 DSH 会话接入。已完成[固定版本源码核查](../../architecture/references/2026-11-03-qq-bridge-session-review.md)。正式链路推荐直接在受控 DSH Agent/session 内运行；当前预览的 llm.stream 不是长期默认架构。建议采用“可见内部反思＋受控 QQ 发送工具”，让显式反思、实际发言与回执成为不同来源；后台整理应覆盖双向对话而非只看用户消息。具体接线仍是建议，未实施。

沿用已有推荐的“LifeCore 保存正式生命与领域规则、DSH 执行模型、组件提供受控能力”。记忆沿用 SeekMemory 窄候选处理优先的建议；具体依赖与质量准入仍见[记忆接入设计](2026-11-02-memory-integration-boundaries-design.md)。

不将“长 session 直接塞全部历史”作为连续性方案：窗口有限，删除/纠正与换模型也不能依赖它。不将“每次新会话只有一段摘要”作为完整方案：摘要可能漏掉刚发生的事、人物或未发出的消息。推荐使用正式状态＋近期耐久记录＋受控长期召回＋可核对交接包。

## 3 一轮消息的完整链条

| 步骤 | 输入与处理 | 持久结果和用户感受 |
| --- | --- | --- |
| 1 接收 | M10 核对 QQ 账号、发送者、私聊/群、源消息 ID；M12 绑定可信场景 | 不用昵称识人；重复投递不重复回复 |
| 2 入账 | M03/M02 保存来源修订、回复待办、记忆整理待办与必要纠正屏障 | 已接收的消息不因后续模型失败而丢失 |
| 3 还原本轮状态 | 读取同一 life_id 的身份/人格，以及当前对象获准的关系、情绪、近期原文、未完话题和相关长期记忆 | 长期整理尚未完成的新消息，也能通过近期记录进入上下文 |
| 4 评价当前输入 | 对新事件形成一次有来源的情绪评价；确定性规则校验强度、时间和变化范围，必要时使用受限模型做语义评价 | 新消息能影响这一次回答；不必等回复结束才产生反应 |
| 5 提交输入侧状态 | 将获准情绪变化按事件幂等提交；复杂关系/成长评价可后置；不等待长期记忆全部整理 | 回答生成失败也不抹掉已经发生的输入与有效反应 |
| 6 生成回复 | M09 装配最新获准状态、近期材料和记忆，M14 调用 DSH；模型输出回复候选及依据 | 语气受当前状态影响，但不编造往事、擅自修改权限或人格 |
| 7 发送与核对 | M02 检查依赖和取消状态；M11 保存固定目标/正文的动作，再交 M10 发送 | 生成、发送成功和结果未知分开；重试不能重复发送 |
| 8 后台整理 | M04 提炼候选，校验证据并提交规范记忆，异步生成检索投影 | 不逐条询问是否记住；未发送回复不当作双方共同经历 |
| 9 长期演进 | M07 归并独立证据，考虑支持/反对、惯性和变化预算，提交修订或保留原状 | 多次相处可能改变偏好/习惯，单次情绪不直接改写人格 |

步骤 4 的语义评价可能增加模型调用，需单独统计延迟/费用；不承诺一轮永远只调用一次模型。可用确定性规则处理的情况不强制调用；语义评价失败则保持已有有效情绪状态并继续合法的普通回复，不杜撰精确情绪变化。记忆服务不可用仍遵循已有核心故障准入，不能用这一降级绕过记忆故障阻断。

若在后续整理中修正原评价，引用同一事件形成修订并重算贡献，不再累加一次情绪刺激。真正收到新反馈是新事件。发出成功与未知结果只提供事实，不自动给情绪加分；任何回执引起的状态影响也必须有独立、幂等的规则。

## 4 会话切换到底切什么

四种标识分别管理：`life_id` 是同一生命，`person_id` 是当前人物，`scene_id` 是交流和权限边界，`session_id` 是可替换的模型执行容器。再有 `turn_id`、场景绑定代次与模型路由版本，用来防止旧任务返回后覆盖新状态。

| 情况 | 延续什么 | 重新检查/切换什么 |
| --- | --- | --- |
| 同一人隔一段时间继续聊 | 身份、获准记忆、关系、有效情绪与未完话题 | 当前时间、许可、近期信息完整性；不强制重新认识 |
| 上下文接近上限，自动换段 | 同一场景、同一人物、正式状态和对话连续性 | 新执行 session 与交接覆盖；不搬整库历史 |
| 手动开启新会话 | 默认延续身份、关系和长期记忆 | 默认清理当前工作上下文；是否接续未完话题由该操作明确选择，不等于删除记忆 |
| 切换模型 | 正式身份、人格版本、经历与任务 | 端点权限、窗口、工具、费用和模型路由；语气可能变化 |
| DSH 正常重启 | 耐久状态、已接收消息、可恢复待办 | 旧租约/未知发送/绑定和当前权限，不能重新出生 |
| 切换聊天对象或进入群聊 | 同一个生命及允许跨场景的状态 | 人物、场景、工具与材料范围；不得带入另一私聊正文、理由或摘要 |

“新会话”“不延续这段话题”“删除某段记忆”“重新出生”必须是不同操作，不能将清空聊天窗口实现为清空人生。正式生命的重新创建不属于本轮普通会话控制。

### 4.1 自动换段协议

1. M09 根据真实总请求窗口、输出预留和配置阈值提出换段；不把旧稿 32k/70% 作为所有模型固定常量。
2. M02 取得场景切换权，固定已耐久来源水位、已发送结果和未处理输入。新 QQ 消息继续入账，但只进入一个待办队列，不同时投给新旧执行器。
3. 形成交接包：当前话题、用户已明确的约束、已解决/未解决事项、必要近期原文、来源版本、摘要覆盖/缺口、未知动作和状态引用。身份/人格等在启用新 session 时读取最新获准版本，不依赖旧摘要里的副本。
4. M12/M09 核对来源、控制代次、授权与完整性；M14 在未驱动的受限作用域准备新 session。摘要成功不代替原始记录存在，长期提炼可晚于换段完成。
5. 在 M02 的可信绑定中原子切换有效代次和待办归属；新旧宿主 session 的创建/关闭本身不是数据库原子操作。新 session 仅在绑定提交后可领取任务；未绑定的孤儿 session 不得执行。
6. 旧代次禁止新生成/发送许可；已在途外部发送交 M11 核对，不重新生成同一次回复。新 session 领取尚未处理的输入，从已确认的交接位置接续。

正常换段优先等当前回合到安全边界；用户强制切换则取消尚未发送的生成并使旧候选失效。切换前已保存/已发送/发送未知的动作不能被“取消回合”删除；未知状态先核对。

摘要失败时，能在预算内用获准原文和结构化未完事项完成完整交接，可走明确的原文回退；否则保持场景切换受阻，继续接收获准消息并显示原因，不切成空白人格。崩溃在绑定切换前后均以持久绑定和任务处置为准，不凭哪个 session 还活着猜测。

### 4.2 防止近期记忆空档

最近消息、已发送回复、纠正屏障与未完话题来自规范记录，不依赖向量索引。长期整理有连续覆盖水位及缺口；M09 合并长期召回与尚未整理的近期来源，按来源/修订去重，不因有摘要就默认中间没有遗漏。

用户刚说“我搬家了”随即换段，即使后台未提炼，新地址陈述仍在近期来源中；旧当前地址被标记待协调，不继续作为无争议当前事实回答。模型不得在未知确切新值时自行补全。

## 5 情绪和人格的两个反馈环

**快环：**新消息 → 与当前目标/关系相关的评价 → 有界情绪变化 → 本轮表达 → 保存依据。即时情绪与慢心境分开；显式非负时间衰减，重启不随机归零。离线被动衰减沿用整合报告的建议，尚未确认为固定产品规则。

**慢环：**独立经历 → 去重证据族 → 支持/反对评价 → 变化窗口与预算 → 新人格版本 → 后续表达。出生原稿不被覆盖，偏好/习惯与稳定倾向采用不同惯性。按用户同日最新要求，身份“大肥鱼”及对已绑定主人的基本信任不可演进，其他性格允许缓慢变化；开发先后不改变此产品目标。

M05 管情绪，M06 管针对人物的关系，M07 管人格。模型不能用“我以后再也不相信人了”这句生成文字直接改三个模块。转发、自己的反思、对同一件事反复检索不能制造更多独立证据。

所有证据贡献带来源权限，不维护多份可独立成长的人格。较早[全模块报告 M05–M07](2026-11-03-full-system-design-report.md)采用严格按可见贡献重算；最新细化稿建议明确允许有限全局心境/抽象人格字段延续，但不提供私聊原因、原文、对象感受或关系明细。该语气影响与隐私取舍仍待审阅；未获准共享的维度继续来源过滤，不把隐藏原因当作已经实现严格无影响隔离。

## 6 最小控制面

| 控制/查看项 | 需要展示或执行的内容 |
| --- | --- |
| QQ 连接与人物绑定 | 当前专属账号、主人绑定、连接/重连缺口、允许对象 |
| 会话状态 | 当前话题、正常/交接中/受阻、未处理消息；新会话与接续/不接续选项 |
| 记忆 | 搜索与来源、处理中/已提交/索引受阻、纠正与删除、主动联想开关 |
| 情绪 | 当前有效状态、允许查看的原因、自动更新与表达强度、留痕修正 |
| 人格 | 出生原稿、当前版本、偏好/习惯变化及证据、暂停自动演进 |
| 总控制 | 全部暂停、模型/预算设置、恢复检查和未知发送核对 |

用户看到“已经记住/改正”必须有对应正式提交；来源保存与长期提炼进度分别表达。删除包括近期上下文、摘要、记忆索引、情绪/关系/人格贡献和旧 session；在清理完成前先阻断使用。

旧备份恢复沿用[共同契约 9.3](2026-11-02-common-contracts.md#93-恢复旧备份有额外限制)：恢复接收边界无法证明时，可能属于旧重送的消息隔离，不能再次产生回复、情绪累加或成长。普通重启与旧备份恢复不能采用同一个自动重放策略。

## 7 此链条何时算搞定

以下是待实施的验收要求，不是已通过的测试：

| 编号 | 场景与验收结果 |
| --- | --- |
| Q01 | 真实 QQ 消息只有一个正式回复者，入账、生成和发送三阶段可追踪；重复投递无重复效果 |
| Q02 | 告知称呼、偏好和共同经历，换段/新会话后按选择延续，能查到支持回答的来源 |
| Q03 | 刚纠正事实立即切 session，整理未完成也不继续使用旧当前值 |
| Q04 | 自动换段同时收到新消息，新旧执行器不双答、不漏已接收待办；交接来源无静默缺口 |
| Q05 | 切换生成中、绑定切换前后、发送后回执前分别崩溃，恢复不重复发送、不复活旧候选 |
| Q06 | 切换人物/群场景，不带出另一私聊的内容、摘要、状态理由和未授权贡献；全局心境/抽象人格若获准共享，按明确允许字段单独验收 |
| Q07 | 同一输入可影响当轮情绪表达；生成失败不丢输入侧状态；重复整理不重复刺激 |
| Q08 | 重启/时钟回拨的情绪变化可解释；情绪规则固定输入可重放，离线无虚构刺激 |
| Q09 | 多次独立经历可触发有预算的偏好/习惯变化；单次辱骂和反复自述不导致人格骤变 |
| Q10 | 删除一条经历后，近期/长期/交接/派生状态不继续使用；旧备份不能恢复可用性 |
| Q11 | 关闭主动联想仍可记忆及明确回忆；暂停成长不关闭正常聊天；新会话不等于删除记忆 |
| Q12 | 换模型保持 life_id、出生原稿和人格版本，重新核验窗口/费用/端点；不保证表达风格完全一致 |

Q01–Q12 复用既有 E01–E14、C01–C32 与记忆验收中的对应场景，不以一次顺利聊天替代故障、中文质量和恢复测试。

## 8 推进顺序与尚未冻结的选择

先固定入站/回执和近期连续性 → 完成正式记忆与纠正链 → 完成自动交接、手动新会话和重启 → 接入情绪快环 → 接入人格慢环 → 跑完整链的隔离/删除/故障验收。用户控制和数据保护贯穿每一步。

第一条主人私聊范围、手动新会话的未完话题选择、情绪维度/衰减、跨场景全局心境共享策略、模型与费用/延迟预算均需在设计确认与实验配置中明确。身份和主人信任固定、其他性格可缓慢演进已由用户确认，不再作为未决开关。本稿给出推荐行为，不将未回答的选择变成用户决议。当前不生成安装或施工命令，不沿用旧 v0.1 授权自动开工。
