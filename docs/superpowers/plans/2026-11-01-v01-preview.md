# LifeCore v0.1 Preview Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline; steps use checkboxes.

**Goal:** Deliver an installable DSH plugin with a visible, persistent first-life experience, SnowLuma transport, and a resumable browser activity foundation.

**Architecture:** DSH is the sole host. A JavaScript host plugin manages one Python 3.12 SQLite worker and exposes an authenticated local management page. SnowLuma is the ordinary-QQ transport. All life changes go through the worker; models and platform calls run outside database transactions.

**Tech Stack:** Node 22.16+, JavaScript ES modules, Python 3.12 stdlib/sqlite3, native browser UI, Playwright for browser integration/QA. No standalone LifeCore server required for installed operation.

**Spec:** ../specs/2026-11-01-lifecore-complete-design.md and ../../architecture/modules/M01-birth-flow.md, corrected by the user's explicit decisions in this chat: DSH, ordinary QQ, SnowLuma, start v0.1 now.

## Global Constraints

- Preserve existing uncommitted documentation. Work on codex/v0.1-preview in the current checkout.
- User authorized implementation after discussion; do not reopen the host decision or wait for another planning approval.
- No account login, QQ sends, avatar/space changes, publication or formal birth on the user's behalf.
- First build is a preview, not completion of G0-G6. Raw events and bounded context first; full SeekMemory integration/four-layer memory follows separately.
- Data lives outside plugin code. Tests use temporary databases and synthetic accounts.
- Do not silently fall back to a different model, recreate identity on database failure, or retry unknown sends.
- No mandatory AstrBot, NapCat, external database or model weights.
- Local DSH reference: 0.2.1-rc.3; verify actual plugin loading before claiming compatibility.

## Review Focus

- Repeated birth and concurrent writes: only one life, draft revision checked.
- Trial/local/QQ scenes: no private cross-scene context or trial inheritance.
- Pausing or configuration changes during generation: stale results cannot send.
- Transport timeout/disconnection: preserve unknown, never blindly resend.
- Missing Python/model/gateway/browser: management UI remains usable, no fabricated success.
